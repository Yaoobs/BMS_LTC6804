# BMS_LTC6804

面向 9 串锂电池的从机 BMS。硬件是 STM32F103C8T6（64 KB Flash、20 KB SRAM）加一颗 LTC6804：芯片经 SPI 测量 12 个通道上的单体电压，MCU 采集电流和温度，开关充放电 MOS，估算 SOC，并在过压、欠压、过流时进入故障。上位机用 115200 的文本命令切换充电、放电和待机。

控制算法按基于模型的设计（MBD）来做，不在 C 里手写状态迁移和保护判断。充放电状态机、过充过放、安时积分、被动均衡在 Simulink 里建模型，用 Embedded Coder 的 `ert` 目标生成面向 ARM Cortex-M 的 C。生成结果只留下 `step`、`initialize` 和对外信号，Keil 直接编译这些文件。模型在 `Model/` 下按功能分开：`State`、`Protect`、`SOC`、`Cell Balancing`。板上编译的是仓库根目录里对应的 `*_ert_rtw/`。

`os.c` 是模型外面的集成层，不实现算法本身。它把查表、安时积分和 MOS 映射留在这里。采样、读电压、保护和状态机分在五条线程里：电流线程出平均电流，电压线程出一帧毫伏，数据处理线程调用 `SOC_Estimator()` 和 `protect_step()`，控制线程调用 `state_machine_step()` 并写成 MOS 脚电平。改门槛、恢复点或状态迁移时改模型并重新生成，采样和 SPI 不用跟着改。仿真里看过的那份逻辑，和板上跑的是同一份生成代码。

手写代码只留在模型和芯片之间：FreeRTOS 线程、LTC6804 的命令和 PEC、电流窗口、串口、Flash。CubeMX 生成时钟、引脚和内核骨架。被动均衡的选节和放电寄存器封装已经按同一方式生成，控制线程里的两处调用保持注释，硬件没有做均衡。

调度见 `docs/RTOS.md`。SysTick 交给 FreeRTOS。电流 1 ms 采一点，电压大约 100 ms 一帧，保护跟在每一帧后面，上报 1 s 一次。

## 适合先讲的几点

**测量不占着 SPI 空等。** 电压线程 100 ms 只发一次 ADCV 就放开锁。芯片在 7 kHz 模式下大约 2.3 ms 转完 12 节，线程等 4 ms 再分四组读。等待期间电流线程可以采样。基准在初始化时打开并保持，运行中不必每次重唤醒。每组电压带 PEC15，对不上就留下上一次的值。电流和温度采样先拿 SPI 锁，不在时钟翻转时读 ADC。

**周期拆成五条线程。** 电流每个毫秒采一点，满 100 ms 墙钟再平均；电压 100 ms 一帧；数据处理做 SOC 和保护；控制处理命令和 MOS；报告线程 1 s 上报并喂狗。三条业务线程都活着，且栈余量都不少于 128 字节，才喂看门狗，超时大约 8 s。

**电流先平均，再做决定。** 电流线程 1 ms 采一点，满 100 ms 对这一窗最多 100 点求平均，然后清空窗口。求和用 32 位。零点附近 ±1 mV 当成 0，高于偏置为放电（负），低于偏置为充电（正）。过流看这次平均是否越出 ±2000（偏置以外 40 mV），不看单次噪声。

**SOC 用两套算法衔接。** 开路电压查表做整数线性插值，结果是万分比，串口显示成 `78.00%` 这种形式。安时积分的步长是 0.1 s，和电压读取的 100 ms 对齐。电量落在中间段时信任积分；高于 80% 或低于 30%，并且和查表相差超过 10% 时，改用查表值并清掉积分量，修正会留下来。收到待机命令时把 SOC 和总电压写入片内 Flash，下次上电能作为积分起点。

**保护和开关只有一条路。** 过压、欠压带恢复门槛：4200 / 4100 mV，2800 / 3100 mV。未接的节是 0 mV，取最小前换成一个很高的数，不会把欠压锁死。过流标志和这两个标志合成故障输入。控制线程收到一帧结果后走状态机，再按待机、充电、放电、故障改两只 MOS。上电 MOS 保持关闭，直到状态离开待机。待机时充电请求仍优先于故障。

**串口不占着循环发。** 115200 文本协议。收满一行再处理：`C` 充电，`D` 放电，`S` 待机并保存。上报走发送中断，每秒发出 SOC、电流、总电压和两只 MOS 的电平。

相对原厂那圈带屏、蓝牙和大量 `delay_ms` 的程序，这一版把“数秒才保护一次”收成毫秒级节拍：电流 1 ms，电压大约 100 ms，保护跟在每次读完电压之后，保护逻辑来自模型生成代码，不跟在整圈延时后面。

## 运行时在做什么

```text
电流线程 1 ms
    └── 避开 SPI 后采一点。满 100 ms 平均、入队、清空窗口

电压线程 100 ms
    └── 发 ADCV，放开锁等 4 ms，四组各读一次

数据处理线程
    └── 等电压帧 → 最新电流 → SOC → 过流 → 过压/欠压

控制线程
    ├── 命令：C / D / S。S 在状态机之后保存
    └── 结果：并上过流 → 状态机 → 改 MOS

报告线程 1 s
    └── 温度、LED、五行上报。三条线程都活着且栈余量够，才喂狗
```

硬件是 9 节电池接在 LTC6804 的 12 个通道上，第 6、11、12 节不接。总电压按 9 节平均，空通道的 0 mV 不参与欠压判断。

## 串口

| 发送 | 动作 |
| --- | --- |
| `C` 加换行 | 请求充电 |
| `D` 加换行 | 请求放电 |
| `S` 加换行 | 请求待机，并把当前 SOC、总电压写入 Flash |

上报示例：

```text
当前SOC: 78.00%
电流: -150
总电压: 33300 mV
充电MOS: OFF
放电MOS: ON
```

## 工程

| 项 | 内容 |
| --- | --- |
| MCU | STM32F103C8T6，8 MHz 晶振，主频 72 MHz |
| 固件库 | STM32Cube FW_F1 V1.8.6 |
| 工程 | Keil MDK，`MDK-ARM/BMS_LTC6804.uvprojx` |
| 单体监测 | LTC6804，SPI 模式 3，约 281 kbit/s，软件片选 PA4 |
| 电流 / 温度 | PB1、PA0，ADC1 |
| 充电 / 放电 MOS | PB8、PB9，高电平打开 |

业务代码在 `Core/PeripheralSrc/`。状态机、保护、安时积分在各自的 `*_ert_rtw/` 目录。
