# RTOS 方案

周期仍是三档：1 ms 采电流，100 ms 产出电流平均和一整帧单体电压，报告线程按 1 s 做温度和上报。电流平均、单体电压各用一条队列交给数据处理线程。数据处理线程没有自己的周期，阻塞在电压队列上；电流队列空着就沿用上一拍平均。算完再把结果放进下一条队列。命令、发送用同样的方式：谁产生谁入队，只有一个线程取出。

不把 `Os_Task()` 放进一个线程。`Os_Period()`、槽位和周期标志删掉。5 ms、10 ms、50 ms 在裸机里是空的，这里不建线程。状态机、过充过放、安时积分仍用原来的模型函数。上电 5 s 空等、ADC 校准、`LTC6804_initialize()`、`USART1_Init()`、`Store_Init()` 放在 `osKernelStart()` 之前。

内核是 CubeMX 的 FreeRTOS，接口用 CMSIS-RTOS v2。`configTICK_RATE_HZ = 1000`。FreeRTOS 占用 SysTick，`HAL_GetTick()` 在 TIM4。USART1 优先级是 5，和 `configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY` 相同，中断里可以入队。

## 相对裸机

裸机是 `Os_Task()` 协作式轮询：主循环里喂狗、处理串口、`Voltage_Poll()` 一次读完四组，再按 1 ms / 100 ms / 1 s 标志做电流、ADCV 和上报。这些函数已经从 `os.c` 去掉。`SysTick_Handler()` 只跑 FreeRTOS，不再调用 `Os_Period()`。

现在由五条线程分担原来的节拍，计算函数没换：

| 原来 | 现在 |
| --- | --- |
| 1 ms 电流入队，100 ms 对满 100 点的环求平均 | 电流线程自己采、自己按 100 ms 墙钟平均后入队，然后清空这一窗 |
| 主循环里一次读完四组，SPI 一直占着 | 电压线程发 ADCV 后放开锁，等 4 ms，再分四组读 |
| 读完电压就在同一次调用里做 SOC、保护、状态机、MOS | 数据处理线程做 SOC 和保护；控制线程做状态机和 MOS |
| 1 s 里翻转 LED、采温度、空闲才发送 | 报告线程做这三件事。发送进队列，发完再取下一条 |
| 每次进 `Os_Task()` 都喂狗 | 三条存活标志都在，并且五条业务线程栈余量都不少于 128 字节，才喂 |

电流和温度采样会先拿 `spiMutexHandle`。裸机不会在 SPI 发时钟时读 ADC；线程抢占之后必须用这把锁把两件事错开，否则 100 点平均会被几次坏样本拉偏，上报电流能晃到大约 -400～+500。

均衡写配置的函数还在，两处调用保持注释。硬件没有做均衡。

上电仍先空等 5 秒。这 5 秒里每秒喂一次看门狗，ADC、LTC6804、串口和 Store 做完后再喂一次，然后才 `osKernelStart()`。看门狗预分频 256、重载 1250，LSI 按 40 kHz 估算约 8 秒。

程序链接范围是 `0x08000000` 起、长度 `0xFC00`。最后一页 `0x0800FC00` 只给 Store。

## 数据怎么走

```text
1 ms 电流线程
    采样入本线程的窗口
    每 100 ms 做一次平均 ──► current_q ──┐
                                         │
100 ms 电压线程                           ├──► 数据处理线程 ──► result_q ──► 控制线程
    发 ADCV，等 4 ms                      │                     （状态机、MOS）
    四组各读一次，合成一帧 ──► voltage_q ──┘
                                                          └── 抄一份给报告线程

命令中断 ──► cmd_q ──► 控制线程
报告线程 / Store ──► tx_q ──► 发送完成后再取下一条
```

| 队列 | 深度 | 一条消息里有什么 | 谁放入 | 谁取出 |
| --- | --- | --- | --- | --- |
| `current_q` | 1 | 平均电流、本窗口点数、节拍 | 电流线程，每 100 ms | 数据处理线程 |
| `voltage_q` | 1 | 12 节毫伏、总电压、四组 PEC 掩码、节拍 | 电压线程，四组都读完 | 数据处理线程 |
| `result_q` | 1 | SOC、总电压、电流、过压、欠压、过流 | 数据处理线程 | 控制线程 |
| `cmd_q` | 4 | 一行文本，最多 32 字节 | USART1 中断 | 控制线程 |
| `tx_q` | 4 | 一条 96 字节文本 | 报告线程、Store 成功提示 | 发送完成回调 |

深度为 1 的三条测量队列，放入时如果已满，先取出丢掉再放，只留最新一拍。数据处理或控制线程慢的时候，生产者不被堵在队列上，也没有旧拍堆积。

## 四组电压分四次读

要拆开读。入队仍是一帧。

`LTC6804_rdcv()` 一次循环读完 RDCVA～RDCVD，大约 1.4 ms。电压线程不调用它，分四次调用 `LTC6804_rdcv_group()`，一组大约 0.3 ms：上锁、读一组、解锁。等 ADCV 的 4 ms 用 `osDelay(4)`，这段不持有 SPI 锁。

队列里不放“半帧”。SOC 和过充过放要看 12 节里的最大、最小和总电压，一组 3 节到了还不能算。四组都解析完，才把 12 节毫伏和总电压放进 `voltage_q`。某一组 PEC 失败时，这一组留着上一次的毫伏，并在掩码里记下组号。整帧照样入队。

```c
osMutexAcquire(spiMutexHandle, osWaitForever);
LTC6804_adcv();
osMutexRelease(spiMutexHandle);
osDelay(4);
for (group = 1; group <= 4; group++) {
    osMutexAcquire(spiMutexHandle, osWaitForever);
    LTC6804_rdcv_group(group, cell_codes);
    osMutexRelease(spiMutexHandle);
    /* PEC 失败则保留这一组旧码，并在 pec_mask 里记下组号 */
}
/* 12 节换成毫伏并求和，再放入 voltageQueueHandle */
```

`LTC6804_rdcv_group()` 读一组并做 PEC 校验。通过才写入这一组 3 节原始码，失败返回 -1，原始码不动。`LTC6804_rdcv()` 仍是把四组连着读完，电压线程不调用它。运行步骤见下面的电压线程。

## 数据处理用两条队列

电压消息是这一拍的触发。单体电压 100 ms 才有一帧，安时积分的步长也是 0.1 s。数据处理线程阻塞在 `voltageQueueHandle` 上。醒来后用超时 0 把 `currentQueueHandle` 里的平均电流取出来；队列空就沿用上一拍电流。两条消息的节拍允许相差一个 100 ms 窗口。

然后做现在这些计算，顺序不变：

1. 用电压消息里的总电压做查表。`total_voltage == 0` 时不做估算。
2. `InitialSOC != 0` 时用电流消息里的平均电流走 `Ah_Integrator_Estimator_step()`。高于 80% 或低于 30%，并且和查表相差超过 10% 时，改用查表值并清积分量。
3. `InitialSOC == 0` 时按现有规则决定采用查表值还是留下当前 SOC，然后清积分量。
4. `protect_step()` 用这一帧的 12 节毫伏。过流看电流消息：`current >= 2000` 或 `current <= -2000`。
5. 把 SOC、总电压、电流、过压、欠压、过流放进 `result_q`，并抄进报告线程要读的那份快照。

查表、积分和保护仍是原来的函数。数据处理线程只负责从两条队列取数、调用它们、再把结果送出去。运行步骤见下面的数据处理线程。

## 线程

优先级从高到低：电流、控制、电压、数据处理、报告。

| 线程 | 周期 | 做什么 |
| --- | --- | --- |
| 电流 | `osDelayUntil(1 ms)` | 采一个点进本线程窗口。墙钟满 100 ms 就平均并放入 `current_q`，然后清窗口。落后超过 1 ms 就把节拍对齐到现在，不补采 |
| 电压 | `osDelayUntil(100 ms)` | 发 ADCV，`osDelay(4)`，四组各读一次，合成一帧放入 `voltage_q` |
| 数据处理 | 无 | 等 `voltageQueueHandle`，取最新电流，估算并保护，放入 `resultQueueHandle` |
| 控制 | 无 | 先处理 `cmd_q`，再处理 `result_q`。走状态机，改 MOS。均衡写配置的调用仍注释着 |
| 报告 | `osDelayUntil(1000 ms)` | 温度、LED、把快照组帧放入 `tx_q`。三个存活标志都在，且五条业务线程栈余量都不少于 128 字节，才喂狗 |

控制线程不能同时阻塞在两条队列上。命令中断和数据处理线程各置一个线程标志，控制线程等标志，再去对应队列里取。先把已经排着的命令处理完，再处理保护结果。这样一行 `C` 或 `D` 不用等下一帧电压。

命令使状态落到待机，而请求已经是充电或放电时，同一次处理里再调用一次 `state_machine_step()`。两只 MOS 全关只留在这一次里。`S` 先走完状态机，再 `Store_SaveOnStandby()`，保存的是数据处理线程已经发布的那一拍。

均衡写配置只在控制线程、状态机之后：仍是待机才计算并 `send_balance_commend()`，离开待机才 `exit_balance_commend()`。写的时候获取 `spiMutexHandle`，不在电压线程里写。运行步骤见下面的控制线程。

报告线程组帧读的是数据处理线程发布的快照，用 `dataMutexHandle` 只包住那一次拷贝。`sprintf` 在锁外面。温度采样和电流采样先拿 `spiMutexHandle`，再拿 `adcMutexHandle`，包住改通道、启动、读结果。采样不和 SPI 传输重叠。运行步骤见下面的报告线程。

发送完成回调从 `tx_q` 取下一条再启动发送。队列里还有空位时，Store 的成功提示和报告都会入队。队列满时丢掉新的一条。

看门狗放在报告线程。电流、电压、控制每次做完自己的一拍，向报告线程置一个存活标志。三个都看到，并且五条业务线程的栈余量都不少于 128 字节，才喂，然后清掉标志。某个线程停住，或栈余量不够，大约 8 s 内复位。数据处理线程不参与喂狗。上电 5 秒空等期间每秒喂一次，初始化结束再喂一次。

### 电流线程

电流线程自己做平均，窗口不出本线程，不用为环形缓冲再加锁。1 ms 的单个采样点不进队列，只有平均结果出队。1000 条/秒的消息会把时间花在拷贝上。平均按 100 ms 墙钟，不按“凑满 100 个点”。漏采时点数会少于 100。消息里带 `count`，数据处理线程不读它。积分步长仍按 0.1 s，不按点数缩放。

每圈先睡在 `osDelayUntil` 上，到 1 ms 边界醒来。发 ADCV 前入窗时刻写成当前节拍加 100 ms，四组读完前改成加 20 ms。这段时间不入窗，空等的 4 ms 也在其中。未满 100 ms 时不平均、不入队。

SPI 或 ADC 被占用时，这一拍改在取锁处睡，拿到锁再采样。这次耗时超过 1 ms，下一圈把节拍对齐到现在，仍按 1 ms 睡，不把漏掉的点补上。

墙钟满 100 ms 且本窗有点：对本窗原始码求平均，放入 `current_q`。队列深度是 1，超时是 0，不在队列上睡。队列空着就直接放入，数据处理线程下次取电压时把它取走。队列里还有上一条没被取走，就丢掉那一条，再放入这一条。然后清窗口，窗口起点改成现在，回到 1 ms 休眠。满 100 ms 但本窗没有点：不入队，只把窗口起点改成现在，继续按 1 ms 睡。

`CurrentTask` 的步骤：

1. 记下起始节拍 `tick`，再记下本窗口起点 `window`。
2. 每次循环先看现在的节拍。已经比 `tick` 晚了超过 1 ms，就把 `tick` 改成现在，不把漏掉的点补采成一串。
3. `tick` 加 1，`osDelayUntil(tick)`。醒来的间隔是 1 ms。
4. 先获取 `spiMutexHandle`，再获取 `adcMutexHandle`。`osKernelGetTickCount()` 已经不早于 `spiSampleAfter` 时才调用 `Current_SamplePush()`，否则这一拍不入窗。然后按相反顺序释放。1 ms 的 `osDelayUntil` 格子不因为这次跳过而后移。ADC 失败时窗口长度不变。
5. 给报告线程置电流存活标志。
6. 现在距离 `window` 还不到 100 ms，回到第 2 步。
7. 满 100 ms 且 `current_raw_count` 为 0，不入队，只把 `window` 改成现在。
8. 点数大于 0 时调用 `Current_CalcFromAverage()`。对本窗原始码求平均。把 `Current`、`Current_WindowCount()` 和当前节拍放进 `currentQueueHandle`。队列深度是 1，已经满就先取出丢掉再放。`count` 是入窗点数。
9. `Current_WindowClear()` 把 `current_raw_pos` 和 `current_raw_count` 清 0，`window` 改成现在。下一窗只含新点。
10. 回到第 2 步。

采样只把 ADC 原始码放进窗口。100 ms 由 `Current_AverageMvX10()` 按 `(raw_sum × 3300 × 10 + 分母 / 2) / (count × 4096)` 得到 0.1 mV，分母是本窗点数乘 4096。`Current_CalcFromAverage()` 用 `1361 × 10 - avg_x10` 做偏差。±0.5 mV 为 0，超出后乘 `50 / 10`。当前代码已经按第 1～10 步跑起来。第 4 步获取 `adcMutexHandle`。第 5 步置电流存活标志，报告线程喂狗后清掉。

### 电压线程

电压线程只发转换命令、分四组读回、合成一帧放进 `voltageQueueHandle`。查表、安时积分、保护、状态机和 MOS 不在这个线程里。`cell_codes[12]` 留在 `VoltageTask` 里，跨周期保留。原始码 1 LSB = 100 μV，毫伏是 `cell_codes / 10`。12 节都加进总电压。`0xFFFF` 仍会变成约 6553 mV，这一步不过滤。

线程名 `"voltage"`，栈 768 字节，优先级 `osPriorityNormal`，低于电流线程。

每圈先睡在 `osDelayUntil` 上，到 100 ms 边界醒来。拿 SPI 锁后先把 `spiSampleAfter` 写成当前节拍加 100 ms，再发 ADCV，发完立刻放锁。这 100 ms 会在四组读完时被改成「读完后再过 20 ms」。然后 `osDelay(4)` 睡 4 ms，这 4 ms 不占 SPI。然后四组各拿一次锁读回，读完就放锁。第 4 组放锁前把 `spiSampleAfter` 写成当前节拍加 20 ms。

这一拍的取锁、4 ms 等待和四组读取加起来超过 100 ms，下一圈把节拍对齐到现在，仍按 100 ms 睡，不把漏掉的 ADCV 补发。

四组读完就换成毫伏并放入 `voltage_q`，PEC 失败也入队。队列深度是 1，超时是 0，不在队列上睡。队列空着就直接放入，数据处理线程正堵在这条队列上，放入后被唤醒。队列里还有上一帧没被取走，就丢掉那一帧，再放入这一帧。然后置存活标志，回到 100 ms 休眠。

`VoltageTask` 的步骤：

1. 记下起始节拍 `tick`。`cell_codes[12]` 是静态数组，上电为 0。PEC 失败时沿用上一拍。
2. 每次循环先看现在的节拍。已经比 `tick` 晚了超过 100 ms，就把 `tick` 改成现在，不把漏掉的 ADCV 连着补发。
3. `tick` 加 100，`osDelayUntil(tick)`。醒来的间隔是 100 ms。
4. 获取 `spiMutexHandle`，把 `spiSampleAfter` 写成当前节拍加 100 ms，调用 `LTC6804_adcv()`，然后释放锁。命令仍是 `0x0360`。这 100 ms 挡住从这一拍到四组读完之间的电流入窗，空等的 4 ms 也包括在内。四组读完后会改成加 20 ms。
5. `osDelay(4)`。这 4 ms 不持有 SPI 锁。
6. 组号从 1 到 4：获取 `spiMutexHandle`，调用 `LTC6804_rdcv_group()`。返回 0 才写入这一组 3 节原始码；返回 -1 则这三个原始码不动，并把 `pec_mask` 的对应位置 1。bit0 到 bit3 对应第 1 到第 4 组。第 4 组在释放锁之前把 `spiSampleAfter` 写成当前节拍加 20 ms，然后释放锁。
7. 四组都处理完，把 12 个原始码换成毫伏并求和。不管 PEC 是否失败都放进 `voltageQueueHandle`。队列深度是 1，已经满就先取出丢掉再放。节拍用读完时的 `osKernelGetTickCount()`。第一次上电、四组都失败时，毫伏和总电压是 0，也入队。
8. 给报告线程置电压存活标志。
9. 回到第 2 步。

当前代码已经按第 1～9 步跑起来。第 8 步置电压存活标志，报告线程喂狗后清掉。

### 数据处理线程

数据处理线程没有自己的周期。电压帧到了才醒，用这一帧电压和最新的平均电流做估算和保护，结果放进 `resultQueueHandle`。状态机、MOS 和均衡不在这个线程里。调度器里的名字是 `"data"`，函数是 `DataTask`。栈 768 字节，优先级 `osPriorityBelowNormal`，低于电压线程。

平均单节仍由 `SOC_Estimator()` 用总电压除以 9。积分步长仍是 0.1 s，不按电流消息里的 `count` 缩放。

`DataTask` 的步骤：

1. 阻塞在 `voltageQueueHandle` 上，超时用 `osWaitForever`。来一帧才往下走。
2. 用超时 0 取 `currentQueueHandle`。取到就把 `current` 记到 `last_current`；队列空就沿用上一拍。`last_current` 是静态变量，上电为 0。两条消息的节拍允许差一个 100 ms。
3. 把这一帧的 12 节毫伏写入 `cell_voltage`，总电压写入 `total_voltage`，`last_current` 写入 `Current`。
4. 调用 `SOC_Estimator()`。总电压为 0 时函数直接返回，SOC 保持原值。其余顺序不变：`InitialSOC` 非 0 时做安时积分，高于 80% 或低于 30% 且和查表相差超过 10% 时改用查表并清积分；`InitialSOC` 为 0 时按现有规则决定采用查表还是留下当前 SOC，然后清积分。
5. 用刚写入的 `Current` 写 `OC_FLAG`：`Current >= 2000` 或 `Current <= -2000`。
6. 调用 `protect_step()`。它读刚写好的 `cell_voltage`。等于 0 mV 的节仍会在模型里换成 9999。`OV_FLAG`、`UV_FLAG` 仍由模型写。
7. 把 `SOC`、`total_voltage`、`Current`、`OV_FLAG`、`UV_FLAG`、`OC_FLAG` 放进 `resultQueueHandle`。队列深度是 1，已经满就先取出丢掉再放。总电压为 0 时也入队。
8. 获取 `dataMutexHandle`，把 SOC、总电压、电流抄进 `dataSnapshot`，然后释放。`sprintf` 不在这把锁里。
9. 给控制线程置结果标志。
10. 回到第 1 步。

不调用 `state_machine_step()` 和 `JudgeBMSState()`，也不在这里写 `CriticalFault`。当前代码已经按第 1～10 步跑起来。第 9 步会给控制线程置结果标志。

### 控制线程

控制线程没有自己的周期。它不堵在某一条队列上，等命令标志或结果标志，先处理命令，再处理一帧保护结果。状态机和 MOS 在这个线程里。调度器里的名字是 `"ctrl"`，函数是 `ControlTask`。栈 1024 字节，优先级 `osPriorityAboveNormal`，低于电流线程、高于电压线程。保存和清除的成功提示在这个线程里拼串并入队。`configTOTAL_HEAP_SIZE` 现为 8192，否则这个线程创建会失败。

进入循环之前，用超时 0 把 `cmdQueueHandle` 取空并逐行处理。调度器还没运行时，`Control_PostLine()` 会入队但不置命令标志，开头这一次就是把这些行处理掉。进入循环之后，只有命令标志置位才再取队列。

`ControlTask` 的步骤：

1. `osThreadFlagsWait` 等待 `CTRL_FLAG_CMD` 或 `CTRL_FLAG_RESULT`，有一个置位就醒。返回值小于 0 就继续等。
2. 命令标志置位时，用超时 0 把命令队列取空。`"Clear"` 调用 `Store_Clear()`，不改请求，也不走状态机。`"D"`、`"C"`、`"S"` 写入 `StateRequest`，调用 `state_machine_step()`。这一步落到待机，而请求已经是充电或放电时，同一次里再调用一次，然后 `JudgeBMSState()` 一次。两次步进之间不改 MOS。这一行是 `"S"` 时，状态机走完再 `Store_SaveOnStandby()`。其它行丢掉。状态图每次只走一条边，充电和放电互切必须经过待机，所以命令要在同一次处理里把第二步走完，避免两只 MOS 全关留到下一帧电压。
3. 结果标志置位时，用超时 0 取 `resultQueueHandle` 一条。取到后 `CriticalFault = ov || uv || oc`，`state_machine_step()` 一次，`JudgeBMSState()` 一次。结果不改请求。进故障、或从故障回到待机，一步就能完成，和原来每次电压读完只走一步一样。回到待机后，下一次结果还会再走一步。
4. `Control_WriteBalance()`：仍是待机就 `balance_step()`，再在 `spiMutexHandle` 里 `send_balance_commend()`，`balance_on_flag` 置 1。离开待机且标志为 1，就在锁里 `exit_balance_commend()`，标志清 0。计算均衡时不持有这把锁。
5. 给报告线程置控制存活标志。
6. 回到第 1 步。

当前代码已经按第 1～3 步和第 5～6 步跑起来。第 4 步的函数还在，命令路径和结果路径里的调用都注释掉了。第 5 步置控制存活标志，报告线程喂狗后清掉。

接收中断在一行以 `\n` 结束时调用 `Control_PostLine()`。文本最多 31 个字符再加结尾 0；更长、队列已满、或控制线程还没建好，就丢掉这一行。内核已经运行才置命令标志。随即重新 `HAL_UART_Receive_IT()`。不在中断里改 `StateRequest`，也不在中断里保存。

待机图里充电请求仍排在故障前面。命令落到待机后再走的那一步，一条 `"C"` 仍会进入充电。

### 报告线程

报告线程按 1 s 做温度、LED、上报和喂狗。调度器里的名字是 `"report"`，函数是 `ReportTask`。栈 1024 字节，优先级 `osPriorityLow`，低于数据处理线程。

温度采样写进 `temp`，不进上报文本。五行格式仍在 `USART1_SendTxStr()` 里：SOC、电流、总电压、充电 MOS、放电 MOS。MOS 读 GPIO，文字是 ON/OFF。拼串在 `dataMutexHandle` 外面。

`ReportTask` 的步骤：

1. 记下起始节拍 `tick`。
2. 每次循环先看现在的节拍。已经比 `tick` 晚了超过 1000 ms，就把 `tick` 改成现在，不把漏掉的上报连着补发。
3. `tick` 加 1000，`osDelayUntil(tick)`。醒来的间隔是 1 s。
4. 先获取 `spiMutexHandle`，再获取 `adcMutexHandle`，调用 `Temp_SamplePush()`，然后按相反顺序释放。ADC 失败时 `temp` 保持原值。
5. `LEDXToggle()`。
6. 获取 `dataMutexHandle`，把 `dataSnapshot` 里的 SOC、总电压、电流抄到本地，然后释放。`USART1_SendTxStr()` 在锁外拼成五行，放进 `txQueueHandle`。一条 96 字节。现有五行最长大约 81 字节。拼出来超过 96 字节，或队列已满，丢掉这一帧，不截断。
7. 电流、电压、控制三个存活标志都是 1，并且电流、电压、数据处理、控制、报告五条线程的历史最小栈余量都不少于 128 字节时，调用 `HAL_IWDG_Refresh()`，然后把三面旗清 0。少一面，或有一条栈余量不够，这一秒不喂。`configCHECK_FOR_STACK_OVERFLOW` 为 2，栈底被冲掉会停在断言里，看门狗仍会计时复位。`Store` 擦除时自己喂的那几次仍保留。数据处理线程不参与喂狗。
8. 回到第 2 步。

当前代码已经按第 1～8 步跑起来。发送和接收的流程见下面的串口收发。

### 串口收发

接收不再在中断里改 `StateRequest`。一行以 `\n` 结束就交给 `Control_PostLine()`，由控制线程处理。发送不再用一块固定缓冲。报告线程的五行和 Store 的提示都先拼成一整帧，放进 `tx_q`，再由空闲的一方启动中断发送。

收取从 `USART1_Init()` 打开单字节接收开始。`\r` 丢掉。普通字节写入行缓冲，写满 63 字节还没遇到 `\n`，这一行标成丢弃。遇到 `\n` 时，空行或已标丢弃的行清掉缓冲，不入队。否则补上 `\0`，调用 `Control_PostLine()`。每个字节处理完都重新打开接收。

`Control_PostLine()` 看到超过 31 个字符、控制线程还没建好、或 `cmd_q` 已满，就丢掉这一行。`cmd_q` 深度是 4，超时是 0，不在队列上睡。还有空位就放入。内核已经在跑才置命令标志；还没跑就只入队，等控制线程启动时取走。`rx_ready` 不再置位，`RECEICE_DATA_DEAL()` 和 `OnUartLine()` 不在这条路上。

发送由 `USART1_SendTxStr()` 或 `USART1_SendText()` 在调用方栈上拼好一帧，再 `TxQueue_Post()`。超过 96 字节就丢掉，不截断。`tx_q` 深度是 4，超时是 0。还有空位就放入；已满就丢掉新的一帧，不在队列上睡。

放入之后看当前有没有发送在进行。没有，就取出一帧，复制到发送缓冲，`HAL_UART_Transmit_IT()` 发出。已经在发送，这一帧留在队列里。发送完成回调再取下一条；取不到就停，等下一次放入时再启动。启动失败就丢掉这一帧再取下一条，同一次最多试 4 帧。取帧和置忙放在关中断里，避免入队和完成回调同时启动发送。

接收出错时重新打开接收，并清掉半行。这时若发送还在进行，不把这次发送清掉；若发送已经不在进行，按完成处理，继续取下一条。

### 空载电流

空载已经正常。两处都留在代码里。电压线程发 ADCV 前把 `spiSampleAfter` 写成当前节拍加 100 ms，四组读完、放开最后一把锁前改成当前节拍加 20 ms。电流线程按 1 ms 醒来，节拍不早于 `spiSampleAfter` 才入窗。零点 `CURRENT_ADC_BASE_MV` 是 1361 mV。

平均仍是这一窗全部原始码直接平均。`Current_AverageMvX10()` 把原始码收成 0.1 mV，分母是点数乘 4096。`delta_x10 = 1361 × 10 - avg_x10`。高于零点为负。绝对值不超过 5（±0.5 mV，±25 个计数）为 0，超出后乘 `50 / 10`。1 mV 是 50 个计数。

加这 20 ms 之前，一次上电会停在 -200、+300、+50 或 0 里的一档，复位才换。那四档跨了大约 10 mV。当时的零点 1366 和按 3300 mV 计算的参考每次上电都不变，给不出这种分档。电流 1 ms 和电压 SPI 的相位在一次上电里锁死，相位决定这一窗落在扰动的哪一侧。同一毫秒不采、收成一把锁、放锁后再静默 5 ms 只丢掉前面几拍，分档还在，这三步已从代码里去掉。

加上 20 ms 之后，靠近 SPI 的点不再入窗，空载大概率停在 +200，是比当时的 1366 低 4.0 mV。零点电压和 ADC 参考若都来自 3.3 V，参考偏差会在相减时抵消，所以按零点偏高改。先改成 1362 mV，实机再改成 1361 mV 更准。1361 烧录后空载正常。
