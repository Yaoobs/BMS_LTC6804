# BMS_LTC6804 项目概览

基于 STM32F103C8T6 的电池管理系统（BMS）从机固件。MCU 负责采样电流和温度、控制充放电 MOS，并通过串口上报状态、接收文本命令。工程名和 SPI 配置面向 Analog Devices LTC6804 多节电池监测芯片。12 节单体电压每 100 ms 发一次转换命令，满 4 ms 后在主循环里读回。1 s 任务把 SOC、电流和两只 MOS 的电平打成四行文本发出。初始化时已经写入配置，REFON 保持打开。

业务代码在 `Core/PeripheralSrc/`：`os.c` 负责调度和 MOS，`usart1.c` 负责串口收发，`sample.c` 负责电流和温度，`LTC6804.c` 负责单体电压。充放电状态机在 `state_machine_ert_rtw/`。过充过放在 `protect_ert_rtw/`。安时积分在 `Ah_Integrator_Estimator_ert_rtw/`，非待机时由 100 ms 任务调用。`Core/Src` 下的外设初始化由 STM32CubeMX 生成。

## 启动流程

`main()` 依次完成 HAL 初始化、时钟、GPIO、SPI1、ADC1、USART1、IWDG，然后调用 `Os_Init()`，进入 `while (1)` 反复执行 `Os_Task()`。

`Os_Init()` 先空等 5 s，再做下面三件事。GPIO 初始化阶段 PB8、PB9 是低电平。打开两只 MOS 的语句已注释，上电后保持关闭，直到状态机离开待机。

1. 校准 ADC1。
2. 调用 `LTC6804_initialize()`：片选拉低 1 ms 唤醒芯片，空等 10 ms，再写入配置。第 0 字节 `0xFC` 打开 REFON，ADCOPT 保持 0。
3. 启动 USART1 单字节中断接收。

## 调度

时基是 SysTick，1 ms 一次。`SysTick_Handler()` 在 `HAL_IncTick()` 之前调用 `Os_Period()` 置位周期标志。`Os_Task()` 在主循环里消费这些标志，属于协作式调度，任务函数本身不再延时。

`Os_Period()` 用 1～5 的槽位把 1 ms 节拍拆开，注释里的“5 ms × N”按这个节拍理解：

| 任务 | 实际周期 | 当前内容 |
| --- | --- | --- |
| `Task_1ms` | 1 ms | 电流采样入队。过流判断已注释，返回 -1 的关断目前不会发生 |
| `Task_5ms` | 5 ms | 空 |
| `Task_10ms` | 10 ms | 空 |
| `Task_50ms` | 50 ms | 空 |
| `Task_100ms` | 100 ms | 对 100 点电流窗口求平均，再发 ADCV，然后按状态更新 SOC |
| `Task_1000ms` | 1 s | 翻转 LED，温度采样并换算，空闲时发送四行文本 |

每次 `Os_Task()` 先喂狗，处理已经收齐的一行串口文本，再调用 `Voltage_Poll()`。发 ADCV 满 4 ms 时，它一次读完四组寄存器，先把 `cell_codes` 换成毫伏并累加总电压，再调用 `protect_step()`。回到 `Os_Task()` 后，用 `OV_FLAG || UV_FLAG` 写入 `CriticalFault`，调用一次 `state_machine_step()`，再由 `JudgeBMSState()` 按 `BMS_State` 改写两只 MOS。周期任务排在这之后。1 ms 标志每个节拍都会置位；5 ms 及以上任务分占不同槽位，互不挤在同一次 5 ms 边界上。

`SetModelInput()`、`SetModelOutput()` 是空函数。`os.h` 声明了 `ShowInformation()`，工程内没有定义，也没有调用。

## 电流采样

电流在 `sample.c` 里分两步做。`Task_1ms()` 调用 `Current_SamplePush()`，读取 PB1（ADC1_IN9），毫伏写入长度 100 的环形缓冲。`Task_100ms()` 先调用 `Current_CalcFromAverage()`，对缓冲取平均后再换算 `Current`，然后发 ADCV。100 个点 × 1 ms 等于 100 ms。同一次主循环里 1 ms 任务在 100 ms 任务前面，本轮新采样会进入本次平均。求和用 `uint32_t`。

- 12 位、右对齐、软件触发，采样时间 239.5 个 ADC 周期。
- 单次毫伏：`mV = (uint16_t)(3.3 × raw / 4096 × 1000)`。缓冲是 `uint16_t`，`Current` 是 `int16_t`。
- 偏置 `CURRENT_ADC_BASE_MV = 1368` mV。平均毫伏高于 1370：`Current = -(adc - 1368) × 50`。低于 1366：`Current = (1368 - adc) × 50`。1366～1370 mV 为 0。高于偏置为负，低于偏置为正。`Current` 是 `int16_t`，绝对值超过 32767 会绕回，大约对应偏离偏置 655 mV。
- 采样函数里有一段已注释的判断：单次毫伏与 1368 的差大于 40 mV 就返回 -1。40 mV 乘 50 等于 2000。它比较的是第一笔单次采样，不是 100 点平均。取消注释后，偏置还没稳在 1368 mV 时上电就会返回 -1。`Task_1ms()` 看到 -1 会关掉两只 MOS，之后返回 0 也不会再打开。现在这段不执行。
- ADC 失败返回 `0xFFFF` 时，采样函数返回 -2，不入队，也不关 MOS。
- 缓冲未满时，平均已经采到的点数。满 100 个后，新点覆盖最旧的点。

`× 50` 是代码里的比例系数。1 s 文本用 `%+d` 上报最近一次 100 ms 算出的 `Current`，正数带 `+`，负数带 `-`。读四组电压寄存器大约 1.4 ms，每 100 ms 会盖住一次 1 ms 电流采样，窗口里会少一个新点。

## 温度采样

温度在 `sample.c` 的 `Temp_SamplePush()` 里采样。`Task_1000ms()` 先翻转 LED，再调用它。1 s 一次，采完立刻换算，没有环形缓冲，也没有平均。通道在运行时切换，CubeMX 初始化只配置了通道 9。

按分压关系，10 kΩ 为上拉，NTC 在下方对地：

```
Rt = 10000 × Vadc / (3.3 - Vadc)
T(°C) = 1 / (1/298.15 + ln(Rt/10000) / 3950) - 273.15
```

即 25 °C 时 10 kΩ、B = 3950 的 NTC。结果加 0.5 后截成 `uint8_t`。能通过判断的原始码是 1～4095，对应大约 -90 °C～528 °C。`uint8_t` 放不下 0 °C 以下，高于 255 °C 只留低 8 位。当前这四行文本不上报温度。

ADC 失败、分压为 0 V 或 3.3 V 时直接返回，不改 `temp`，避免 `3.3 - adc` 变成 0。上电后还没有成功采样时，`temp` 为 0。

## 串口

收发在 `Core/PeripheralSrc/usart1.c`。波特率 115200，8 数据位，无校验，1 停止位。接收在中断里逐字节拼一行，命令执行在主循环。USART1 中断优先级为 0，SysTick 为 15，收字节可以打断节拍。上位机要使用文本模式，让换行成为字节 `0x0A`。十六进制模式发出的 `44` 后面如果没有 `0A`，这一行不会结束。`os.c` 仍负责在初始化时打开接收，在主循环里调用 `RECEICE_DATA_DEAL()`，并在 1 s 任务里调用 `USART1_SendTxStr()`。

### 下行

中断每收到一个字节写入 `rx_str[]`，最长 63 个字符，末尾留一个 `\0`。`\r` 丢掉，也不结束这一行。收到 `\n` 且这一行里已经有字符时，写入 `\0` 并把 `rx_ready` 置 1，同时暂停继续接收。空行和超长后还没看到换行的内容会被丢掉。`RECEICE_DATA_DEAL()` 看到 `rx_ready` 后把这一行拷出来，清掉 `rx_ready`，重新打开接收，再调用 `OnUartLine()`。一行还没结束时，`OnUartLine()` 不会运行。

`OnUartLine()` 只认整行正好是这三行，多一个空格也不相等：

| 收到的一行 | `StateRequest` |
| --- | --- |
| `D` | `Driving`（2） |
| `C` | `Charging`（1） |
| `S` | `Standby`（0） |

其它内容不改 `StateRequest`。它的初值是 0，也就是待机。UART 错误回调清掉当前半行和丢弃标志，并把 `tx_busy` 清 0。已经收齐、还没被主循环取走的那一行保留，此时不重新打开接收。

### 状态机与 MOS

生成代码在 `state_machine_ert_rtw/state_machine.c`。每次 `Os_Task()` 在电压读取之后调用 `state_machine_step()`，再调用 `JudgeBMSState()`。

| `BMS_State` | MOS |
| --- | --- |
| `BMS_Standby`（0） | 充电、放电都关 |
| `BMS_Driving`（2） | 充电关，放电开 |
| `BMS_Charging`（1） | 放电关，充电开 |
| `BMS_Fault`（3） | 充电、放电都关 |

每次 `Os_Task()` 在 `Voltage_Poll()` 之后执行 `CriticalFault = OV_FLAG || UV_FLAG`，再调用 `state_machine_step()`。待机时，`StateRequest` 为 `Charging` 优先进入充电，其次才看 `CriticalFault`，最后才是放电请求。已经在充电或放电时，故障优先于请求，直接进入故障；请求变化则先回到待机。同一次 `step()` 不会再从待机跳到另一个运行状态。故障里忽略 `StateRequest`，只有 `CriticalFault` 变 0 才回到待机。

### 上行文本（每秒一次）

`Task_1000ms()` 先翻转 LED、采样温度。`tx_busy == 0` 时调用 `USART1_SendTxStr()`。它把四行写进 `tx_data[100]`，长度是逐次追加后的 `len`，再交给 `USART1_SendData()`。`SOC` 为 7800、电流为 -150、充电 MOS 打开、放电 MOS 关闭时，线上是：

```text
当前SOC: 78.00%
电流: -150
充电MOS: ON
放电MOS: OFF
```

SOC 按万分比存放，发送时拆成 `SOC / 100` 和 `SOC % 100`。电流用 `%+d`。`ON` / `OFF` 来自当时的 PB8、PB9 电平，高电平为 `ON`。`tx_busy` 上电为 0，第一秒就会启动。发送使用 `HAL_UART_Transmit_IT()`，完成后 `HAL_UART_TxCpltCallback()` 把 `tx_busy` 清 0。返回值不是 `HAL_OK` 时立刻清 `tx_busy`。这一秒还没发完时，下一秒看到 `tx_busy == 1` 就跳过。50 字节二进制组帧函数已整段注释。

## 单体电压

`Task_100ms()` 在电流平均之后调用 `LTC6804_adcv()`，再记下 `HAL_GetTick()`。`cell_codes[12]` 保存 12 节原始码。

1. ADCV 命令高字节 `0x03`、低字节 `0x60`，PEC 由 `pec15_calc()` 现算。片选拉低只包住这 4 个字节。通道位 CH 是 `000`，12 节一起转换。模式位 MD 是 `10`，即 7 kHz。放电允许位 DCP 是 0，转换期间不开启均衡。
2. 主循环里的 `Voltage_Poll()` 用 `(uint32_t)(HAL_GetTick() - adcv_tick) >= 4` 判断时间到了再读。初始化已把 REFON 打开，每次转换不再等待基准上电。7 kHz 全节转换大约 2.3 ms，4 ms 门槛盖住这次转换。等待期间主循环继续转，不再调用 `HAL_Delay()`。
3. 时间到了之后，`LTC6804_rdcv()` 一次读完 RDCVA～RDCVD，命令分别是 `0x0004`、`0x0006`、`0x0008`、`0x000A`。每组时钟出 8 字节：6 字节电压加 2 字节 PEC。四组合计大约 1.4 ms。
4. PEC 通过后，按低字节在前解析 3 节，写入 `cell_codes[(reg - 1) * 3 + 0..2]`。1 LSB = 100 µV。PEC 失败则这一组保持旧值。
5. 返回值没有使用。某一组失败时，其余组仍会更新。

1 s 任务不再做电压换算，文本上报也不带单体电压。读完寄存器后，`Voltage_Poll()` 调用 `Get_TotalVoltage()`：`cell_codes[i] / 10` 得到毫伏，整数除法去掉不足 1 mV 的部分，写入 `cell_voltage[]` 并累加进 `total_voltage`。下标 0 是第 1 节。ADCV 每 100 ms 一次，读数大约在发命令 4 ms 之后更新。

## SOC

`Get_SOC()` 返回百分比，范围是 0～100。`Task_100ms()` 在发完 ADCV 后调用 `SOC_Estimator()`。待机时 `SOC = Get_SOC() × 100`，再把这个万分比写进 `InitialSOC`。100% 对应 10000，串口显示 `100.00%`。没有命中任何一档时返回 0，待机分支会把 `SOC` 和 `InitialSOC` 都写成 0。

表按 50 mV 一档往下减。高于 `4100 × 9` mV 记为 100。从 `3550 × 9` 到 `4100 × 9` 大约每降 50 mV，百分比减 1，落在 77～90。再往下跳档：`3450 × 9` 到 `3500 × 9` 是 40，然后 30、20、10、5。

查表条件都是严格大于和严格小于，等于门槛的电压哪一档都进不去，这时返回 0。第一档 `> 4100 × 9` 已经包含了 `4100 × 9` 到 `4150 × 9`，后面的 95 那一档到不了。`3900 × 9` 到 `3950 × 9` 写了两次，先写上的 86 生效，85 到不了。

充电或放电时调用 `Ah_Integrator_Estimator_step()`。模型版本 1.49。它读 `Current` 和 `InitialSOC`，两边都按万分比衔接。额定容量 `Q_rated = 1200`，库伦效率 `eta_coulomb = 0.99`，类型是 `real32_T`。积分每次加上 `0.99 × Current × 0.1`，正电流和负电流都乘这个系数，和 100 ms 调用周期一致。结果是 `(积分量 / (3600 × Q_rated) + 9.99998301e-5 × InitialSOC) × 10000`，再收成 `uint16_T` 的 `SOC`。`9.99998301e-5` 把万分比还原成小数，乘 10000 后再变回万分比。`InitialSOC` 为 7800、积分量仍为 0 时，结果仍是 7800，串口显示 `78.00%`。待机期间查表会盖掉 `SOC` 和 `InitialSOC`，并调用 `Ah_Integrator_Estimator_initialize()`，把积分量写成 0。下次进入充电或放电时，从这次查到的 `InitialSOC` 重新累加。

实际接了 9 节。未接的第 6、11、12 节读数是 0，12 路相加等于这 9 节之和，和门槛里的 `× 9` 一致。未接通道如果读到非 0，仍会加进 `total_voltage`。

## 过充与过放

手写的 `Judge_CHG_DSG()` 和 `Get_Cell_Voltage_Max_Min()` 已整段注释。标志改由 `protect_ert_rtw/protect.c`（模型 1.38）在每次电压读完时计算。`Voltage_Poll()` 先调用 `Get_TotalVoltage()`，再调用 `protect_step()`，比较的是本拍毫伏。`Os_Task()` 再用这两个标志驱动故障状态，`JudgeBMSState()` 在故障时关掉两只 MOS。

取最小之前，等于 0 mV 的节换成 9999 mV，未接的三节因此不拉低最小。最大仍用原始毫伏，0 mV 也不会抬高最大。状态只有正常、过压、欠压三种，不能同时置两个标志。第一次 `protect_step()` 只进入正常并把两个标志清 0，不看电压。之后：

| 当前状态 | 条件 | 结果 |
| --- | --- | --- |
| 正常 | 最小节 `< 2800` mV | 欠压，`UV_FLAG = 1` |
| 正常 | 否则最大节 `> 4200` mV | 过压，`OV_FLAG = 1` |
| 过压 | 最大节 `< 4100` mV | 回到正常，两个标志清 0 |
| 欠压 | 最小节 `> 3100` mV | 回到正常，两个标志清 0 |

未接三节保持 0 mV 时，不会再把欠压锁住。等于 0 mV 的已接节同样被换成 9999 mV，不参与欠压。非 0 的读数，包括未接通道上的噪声和约 6553 mV 的 `0xFFFF`，仍参与最大，也会参与最小。`Temp_up_flag`、`OC_FLAG` 已定义。过流返回 -1 的那段已经注释，`OC_FLAG` 现在不会被置 1。

SPI 仍是模式 3、软件片选 PA4、SCK 约 281.25 kbit/s，接的是芯片的 SPI 口。`LTC6804_initialize()` 上电时把片选拉低 1 ms 做一次唤醒，空等 10 ms，再调用 `LTC6804_wrcfg()` 写入 `0xFC`。

看门狗超时大约 2 s，超时后整片进入睡眠。100 ms 就会发一次 ADCV，大约 4 ms 后再读寄存器，间隔小于 2 s，芯片不会在两次采样之间睡下去，所以每次测量前不必再唤醒。大约 5.5 ms 的那个时间是 isoSPI 口自己的空闲超时，不是这颗芯片接 SPI 时的睡眠看门狗。

## 运行关系

```
SysTick 1 ms
    └── Os_Period() 置位 1/5/10/50/100/1000 ms 标志

USART1 中断
    ├── 收：拼到 \n 后置 rx_ready，并暂停接收
    └── 发：文本发完后把 tx_busy 清 0

主循环 Os_Task()
    ├── 喂狗
    ├── 取走一行文本，写入 StateRequest，并恢复接收
    ├── Voltage_Poll()：满 4 ms 则读完 12 路，先换成毫伏并累加总电压，再 protect_step()
    ├── CriticalFault = OV_FLAG || UV_FLAG，再 state_machine_step()，按 BMS_State 重写两只 MOS
    ├── 1 ms：电流采样入队。过流返回 -1 的判断已注释
    ├── 100 ms：电流窗口平均，发 ADCV，再按待机查表或按充放电做安时积分
    └── 1 s ：翻转 LED，温度采样并换算；tx_busy 为 0 时发送四行文本
```
