# BMS_LTC6804 项目概览

基于 STM32F103C8T6 的电池管理系统（BMS）从机固件。MCU 负责采样电流和温度、控制充放电 MOS，并通过串口上报状态、接收开关命令。工程名和 SPI 配置面向 Analog Devices LTC6804 多节电池监测芯片。12 节单体电压每 10 ms 发一次转换命令，满 4 ms 后在主循环里读回，并放进每秒上报帧。初始化时已经写入配置，REFON 保持打开。

业务代码在 `Core/PeripheralSrc/`：`os.c` 负责调度和串口，`sample.c` 负责电流和温度，`LTC6804.c` 负责单体电压。`Core/Src` 下的外设初始化由 STM32CubeMX 生成。

独立看门狗使用内部 LSI。预分频 256、重载值 1250。按 LSI 典型值 40 kHz 估算，超时约 8 秒。主循环每次进入 `Os_Task()` 都会喂狗。

## 启动流程

`main()` 依次完成 HAL 初始化、时钟、GPIO、SPI1、ADC1、USART1、IWDG，然后调用 `Os_Init()`，进入 `while (1)` 反复执行 `Os_Task()`。

`Os_Init()` 做四件事：

1. 校准 ADC1。
2. 拉高 PB8、PB9，默认同时打开充电和放电 MOS。GPIO 初始化阶段这两个脚是低电平，打开动作发生在 `Os_Init()`。
3. 启动 USART1 单字节中断接收。
4. 调用 `LTC6804_initialize()`：片选拉低 1 ms 唤醒芯片，空等 10 ms，再写入配置。第 0 字节 `0xFC` 打开 REFON，ADCOPT 保持 0。

## 调度

时基是 SysTick，1 ms 一次。`SysTick_Handler()` 在 `HAL_IncTick()` 之前调用 `Os_Period()` 置位周期标志。`Os_Task()` 在主循环里消费这些标志，属于协作式调度，任务函数本身不再延时。

`Os_Period()` 用 1～5 的槽位把 1 ms 节拍拆开，注释里的“5 ms × N”按这个节拍理解：

| 任务 | 实际周期 | 当前内容 |
| --- | --- | --- |
| `Task_1ms` | 1 ms | 电流采样入队 |
| `Task_5ms` | 5 ms | 空 |
| `Task_10ms` | 10 ms | 发 ADCV，并用 10 点窗口平均计算 `current` |
| `Task_50ms` | 50 ms | 空 |
| `Task_100ms` | 100 ms | 空 |
| `Task_1000ms` | 1 s | 翻转 LED，温度采样并换算，空闲时启动中断发送 |

每次 `Os_Task()` 先喂狗，处理已经收齐的串口命令，再调用 `Voltage_Poll()`。发 ADCV 满 4 ms 时，它一次读完四组寄存器，接着算总电压、SOC、已接 9 节里的最大最小电压，并按阈值开关充放电 MOS。然后才按 1 ms 到 1 s 的顺序执行到期任务。1 ms 标志每个节拍都会置位；5 ms 及以上任务分占不同槽位，互不挤在同一次 5 ms 边界上。

`SetModelInput()`、`SetModelOutput()` 是空函数。`os.h` 声明了 `ShowInformation()`，工程内没有定义，也没有调用。

## 电流采样

电流在 `sample.c` 里分两步做。`Task_1ms()` 调用 `Current_SamplePush()`，读取 PB1（ADC1_IN9）并写入长度 10 的环形缓冲。`Task_10ms()` 发完 ADCV 后调用 `Current_CalcFromAverage()`，对缓冲取平均后再换算 `current`。10 个点 × 1 ms 等于 10 ms。同一次主循环里 1 ms 任务在 10 ms 任务前面，本轮新采样会进入本次平均。

- 12 位、右对齐、软件触发，采样时间 239.5 个 ADC 周期。
- 单次毫伏：`mV = (int)(3.3 × raw / 4096 × 1000)`。ADC 失败不入队，保留缓冲里已有的点。
- 缓冲未满时，平均已经采到的点数。满 10 个后，新点覆盖最旧的点。
- 平均毫伏：`adc = (sum + count / 2) / count`，正数四舍五入。
- 偏置 `CURRENT_ADC_BASE_MV = 1349` mV，按空载调到这个值，使空载平均落在死区内。
- 平均毫伏高于 1351：`current = (adc - 1349) × 50`。
- 平均毫伏低于 1347：`current = (1349 - adc) × 50`。
- 1347～1351 mV：`current = 0`。

两个方向算出来都是正数，帧里没有电流方向。窗口内如果电流换向，毫伏平均会互相抵消，上报值仍然没有符号。`× 50` 是代码里的比例系数，单位取决于前端采样电路。1 s 上报使用最近一次 10 ms 算出的 `current`。读四组电压寄存器大约 1.4 ms，每 10 ms 会盖住一次 1 ms 电流采样，窗口里会少一个新点。

## 温度采样

温度在 `sample.c` 的 `Temp_SamplePush()` 里采样。`Task_1000ms()` 先翻转 LED，再调用它。1 s 一次，采完立刻换算，没有环形缓冲，也没有平均。通道在运行时切换，CubeMX 初始化只配置了通道 9。

按分压关系，10 kΩ 为上拉，NTC 在下方对地：

```
Rt = 10000 × Vadc / (3.3 - Vadc)
T(°C) = 1 / (1/298.15 + ln(Rt/10000) / 3950) - 273.15
```

即 25 °C 时 10 kΩ、B = 3950 的 NTC。结果加 0.5 后截成 `int`，写入 `temp`。同一次 1 s 任务组帧时，把 `temp` 的低 8 位放进上报帧。

ADC 失败、分压为 0 V 或 3.3 V 时直接返回，不改 `temp`，避免 `3.3 - adc` 变成 0。这一秒的帧仍带上一次的温度。上电后还没有成功采样时，`temp` 为 0。

## 串口协议

波特率 115200，8 数据位，无校验，1 停止位。接收在中断里逐字节组帧，命令执行在主循环。USART1 中断优先级为 0，SysTick 为 15，收字节可以打断节拍。

### 下行命令（3 字节）

格式：`01` + 命令 + `55`。

| 命令字节 | 动作 |
| --- | --- |
| `0x04` | PB9 置高，打开放电 MOS |
| `0x05` | PB9 置低，关闭放电 MOS |
| `0x06` | PB8 置高，打开充电 MOS |
| `0x07` | PB8 置低，关闭充电 MOS |

首字节必须是 `0x01`，否则丢弃并继续等帧头。收满 3 字节且帧尾为 `0x55` 后置 `cmd_ready`，并暂停继续接收，直到 `RECEICE_DATA_DEAL()` 取走命令再重新打开中断接收。这段窗口内的后续字节会丢失。帧尾不对则丢弃该帧并继续收。UART 错误回调会清空组帧下标，并把 `tx_busy` 清 0；若没有待处理命令，会重新开启接收。接收错误和发送错误走同一个回调。

### 上行上报（50 字节，每秒一次）

`Task_1000ms()` 先翻转 LED、采样温度。`tx_busy == 0` 时调用 `USART1_SendShang(shang)`。总电压、SOC、最大最小节电压在 `Voltage_Poll()` 里已经算好，发送函数只负责装进帧。

`tx_busy` 上电为 0，表示没有发送在进行，所以第一秒就会启动。`USART1_SendShang()` 把帧头、单体电压、总电压、电流、温度和两个 MOS 电平写入 `shang[]`，把 `tx_busy` 置 1，再调用 `HAL_UART_Transmit_IT()`。返回 `HAL_OK` 后函数立即返回，50 字节在 115200 波特下大约 4.3 ms，由 USART1 中断逐字节发出，`HAL_UART_TxCpltCallback()` 把 `tx_busy` 清 0。返回值不是 `HAL_OK` 时，立刻把 `tx_busy` 清 0，下一秒可以再试。这一秒里发送还没完成时，下一秒任务看到 `tx_busy == 1` 就跳过，避免两帧叠在同一块缓冲上。发送期间主循环继续跑 1 ms 电流采样。

`shang[]` 位于 BSS，未赋值的字节保持 0。当前传入的就是 `shang`，填充和发送是同一块缓冲。

| 下标 | 内容 |
| --- | --- |
| 0 | 帧头 `0xAA` |
| 1 | 帧头 `0x01` |
| 2～25 | 12 路单体电压，每节 2 字节，大端，单位 mV。第 1 节在字节 2、3。第 6、11、12 节未接，对应字节为 0 |
| 26～31 | 未使用，为 0 |
| 32～33 | 12 路电压之和，大端，单位 mV。未接的 3 路为 0，数值等于 9 节之和 |
| 34～35 | SOC，大端。查表结果是 5～100，高字节为 0。未命中任何一档时保持上一次的值，上电为 0 |
| 36 | `current` 高字节 |
| 37 | `current` 低字节 |
| 38 | 温度，取低 8 位 |
| 39 | 放电 MOS 脚电平，1 为开 |
| 40 | 充电 MOS 脚电平，1 为开 |
| 41～42 | 已接 9 节里的最大电压，大端，单位 mV。不含第 6、11、12 节 |
| 43～44 | 已接 9 节里的最小电压，大端，单位 mV。不含第 6、11、12 节 |
| 45～49 | 未使用，为 0 |

电流按无符号 16 位大端放入帧中。温度为单字节，负温度会按补码低 8 位出现。

## 单体电压

`Task_10ms()` 调用 `LTC6804_adcv()` 后记下 `HAL_GetTick()`。`cell_codes[12]` 保存 12 节原始码。

1. ADCV 命令高字节 `0x03`、低字节 `0x60`，PEC 由 `pec15_calc()` 现算。片选拉低只包住这 4 个字节。通道位 CH 是 `000`，12 节一起转换。模式位 MD 是 `10`，即 7 kHz。放电允许位 DCP 是 0，转换期间不开启均衡。
2. 主循环里的 `Voltage_Poll()` 用 `(uint32_t)(HAL_GetTick() - adcv_tick) >= 4` 判断时间到了再读。初始化已把 REFON 打开，每次转换不再等待基准上电。7 kHz 全节转换大约 2.3 ms，4 ms 门槛盖住这次转换。等待期间主循环继续转，不再调用 `HAL_Delay()`。
3. 时间到了之后，`LTC6804_rdcv()` 一次读完 RDCVA～RDCVD，命令分别是 `0x0004`、`0x0006`、`0x0008`、`0x000A`。每组时钟出 8 字节：6 字节电压加 2 字节 PEC。四组合计大约 1.4 ms。
4. PEC 通过后，按低字节在前解析 3 节，写入 `cell_codes[(reg - 1) * 3 + 0..2]`。1 LSB = 100 µV。PEC 失败则这一组保持旧值。
5. 返回值没有使用。某一组失败时，其余组仍会更新。

1 s 任务不再做电压换算。读完寄存器后，`Voltage_Poll()` 调用 `Get_TotalVoltage()`：`cell_codes[i] / 10` 得到毫伏，整数除法去掉不足 1 mV 的部分，写入 `cell_voltage[]` 并累加进 `total_voltage`。`USART1_SendShang()` 再把第 `i` 节放到 `shang[2 + 2*i]`（高字节）和 `shang[3 + 2*i]`（低字节），`i` 从 0 到 11，对应字节 2～25。下标 0 是第 1 节。总电压大端写入字节 32、33。上报的是最近一次读数。ADCV 每 10 ms 一次，读数大约在发命令 4 ms 之后更新。

## SOC

`Get_SOC()` 在 `Voltage_Poll()` 里、总电压累加之后调用，大约每 10 ms 一次。它用 `total_voltage` 和 `单节毫伏 × 9` 比较，结果放在全局 `SOC`。发送时再大端写入字节 34、35。没有命中任何一档时不改 `SOC`，上电为 0。

表按 50 mV 一档往下减。高于 `4100 × 9` mV 记为 100。从 `3550 × 9` 到 `4100 × 9` 大约每降 50 mV，SOC 减 1，落在 77～90。再往下跳档：`3450 × 9` 到 `3500 × 9` 是 40，然后 30、20、10、5。

查表条件都是严格大于和严格小于，等于门槛的电压哪一档都进不去，`SOC` 保持原值。第一档 `> 4100 × 9` 已经包含了 `4100 × 9` 到 `4150 × 9`，后面的 95 那一档到不了。`3900 × 9` 到 `3950 × 9` 写了两次，先写上的 86 生效，85 到不了。

实际接了 9 节。未接的第 6、11、12 节读数是 0，12 路相加等于这 9 节之和，和门槛里的 `× 9` 一致。未接通道如果读到非 0，仍会加进 `total_voltage`。

## 过压与欠压

芯片按 12 路采集，电池只接了 9 节。第 6、11、12 节没有电芯，`cell_voltage` 下标 5、10、11 为 0。这三路如果参加比较，最小电压会变成 0，欠压会误关放电。

`Get_Cell_Voltage_Max_Min()` 用第 1 节做初值，再从下标 0 扫到 11，跳过 5、10、11，只在其余 9 节里更新 `Max` 和 `Min`。已接的节读到 0 仍会拉低 `Min`。上报帧字节 2～25 仍带上全部 12 路，未接的三路保持 0。

读完并算出 `Max`、`Min` 之后，`Voltage_Poll()` 按下面阈值开关 MOS。串口命令仍可改这两个脚，下一次电压读完会再按阈值覆盖。

| 条件 | 动作 |
| --- | --- |
| `Max > 4200` mV | 关闭充电 MOS，`OV_FLAG = 1` |
| 已过压且 `Max < 4100` mV | 打开充电 MOS，`OV_FLAG = 0` |
| `Min < 2800` mV | 关闭放电 MOS，`UV_FLAG = 1` |
| 已欠压且 `Min > 3000` mV | 打开放电 MOS，`UV_FLAG = 0` |

过压和欠压互不影响。比较都是严格大于或小于，等于 4200 mV 不会关充电，等于 2800 mV 不会关放电。`Max`、`Min` 大端放进上报帧字节 41～44。`Temp_up_flag`、`OC_FLAG` 已定义，还没有使用。

判断不会在发 ADCV 之前进行。`adcv_wait` 上电为 0，只有 `Task_10ms()` 发出 ADCV 后才置 1；`Voltage_Poll()` 再等满 4 ms，调用 `LTC6804_rdcv()` 之后才算 `Max`、`Min`。已接电芯转换完成后是数千毫伏，不是 0。转换还没结束时，结果寄存器是 `0xFFFF`，换成约 6553 mV，会关充电，不会表现为全 0。未接的三路为 0 已从比较里排除。

已接节变成 0 只发生在这一组 PEC 还从未通过的时候。`cell_codes[]` 上电为 0，PEC 失败不覆盖旧值。某一组第一次就失败时，里面已接的节保持 0，`Min` 为 0，会关掉放电。通过一次之后，再失败会留下上次的电压，不再变回 0。`Min < 2800` 那一行的注释写成了“低于 4200 mV”，执行的阈值是 2800 mV 和 3000 mV。

SPI 仍是模式 3、软件片选 PA4、SCK 约 281.25 kbit/s，接的是芯片的 SPI 口。`LTC6804_initialize()` 上电时把片选拉低 1 ms 做一次唤醒，空等 10 ms，再调用 `LTC6804_wrcfg()` 写入 `0xFC`。

看门狗超时大约 2 s，超时后整片进入睡眠。10 ms 就会发一次 ADCV，大约 4 ms 后再读寄存器，间隔小于 2 s，芯片不会在两次采样之间睡下去，所以每次测量前不必再唤醒。大约 5.5 ms 的那个时间是 isoSPI 口自己的空闲超时，不是这颗芯片接 SPI 时的睡眠看门狗。

## 运行关系

```
SysTick 1 ms
    └── Os_Period() 置位 1/5/10/50/100/1000 ms 标志

USART1 中断
    ├── 收：拼 3 字节命令，置 cmd_ready 后暂停接收
    └── 发：50 字节发完后把 tx_busy 清 0

主循环 Os_Task()
    ├── 喂狗
    ├── 执行充放电开关命令，并恢复接收
    ├── Voltage_Poll()：满 4 ms 则读完 12 路，算总电压、SOC、已接 9 节的最大最小，并做充放电保护
    ├── 1 ms：电流采样入队
    ├── 10 ms：发 ADCV，并做电流窗口平均
    └── 1 s ：翻转 LED，温度采样并换算；tx_busy 为 0 时启动中断发送
```

## 当前没有完成的部分

- `Voltage_Poll()` 不看 `LTC6804_rdcv()` 的返回值。某一组 PEC 失败时，该组保持旧码，其余组仍更新。该组若还从未通过，已接节保持上电时的 0，`Min` 为 0，会关掉放电。通过一次后再失败，留下的是上次电压。原始码 `0xFFFF` 会换成约 6553 mV，并可能被当成最大节电压关掉充电。
- 四组寄存器一次读完，大约 1.4 ms。1 ms 电流采样的标志只有一位，每 10 ms 可能丢掉一次电流采样。
- SOC 查表：等于门槛时保持上一次的值；95 和 85 两档写了但到不了。未接三路为 0 时，总和与 `× 9` 门槛一致；这三路若读到非 0，仍会计入总电压。
- 5 ms、50 ms、100 ms 任务函数为空。`SetModelInput()`、`SetModelOutput()` 为空，`ShowInformation()` 没有实现。
- 电流上报不区分充放电方向。
- 上报帧字节 26～31、45～49 仍未使用。串口命令处理期间会暂停接收。过压或欠压期间，串口打开 MOS 的命令会在下一次电压读完后被保护逻辑关掉。
