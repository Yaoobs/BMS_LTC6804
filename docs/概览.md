# BMS_LTC6804 项目概览

基于 STM32F103C8T6 的电池管理系统（BMS）从机固件。MCU 负责采样电流和温度、控制充放电 MOS，并通过 USART1 的 Modbus RTU 上报状态、接收命令。工程名和 SPI 配置面向 Analog Devices LTC6804 多节电池监测芯片。运行中的调度是 FreeRTOS，步骤见 `docs/RTOS.md`，寄存器见 `docs/modbus.md`。裸机的 `Os_Task()` 协作式轮询已经去掉。

12 节单体电压由电压线程每 100 ms 发一次转换命令，放开 SPI 锁等 4 ms，再分四组读回。报告线程每 1 s 采温度并翻转 LED。总电压、电流、SOC 和两只 MOS 由 Modbus 功能码 `0x03` 读出。初始化时已经写入配置，REFON 保持打开。

业务代码在 `Core/PeripheralSrc/`：`os.c` 保留估算、MOS 映射和上电初始化，`switch.c` 负责两只 MOS 的脚电平，`usart1.c` 负责串口收发，`sample.c` 负责电流和温度，`LTC6804.c` 负责单体电压和均衡寄存器。线程、队列和锁在 `Core/Src/freertos.c`。充放电状态机在 `state_machine_ert_rtw/`。过充过放在 `protect_ert_rtw/`。被动均衡在 `balance_ert_rtw/`，写配置的调用仍注释，见 `docs/被动均衡.md`。安时积分在 `Ah_Integrator_Estimator_ert_rtw/`，在读完单体电压之后由数据处理线程调用。掉电保存的 `soc` 和总电压在 `store.c`。`Core/Src` 下的外设初始化由 STM32CubeMX 生成。

## 启动流程

`main()` 依次完成 HAL 初始化、时钟、GPIO、SPI1、ADC1、USART1、IWDG，然后调用 `Os_Init()`，再 `osKernelInitialize()`、`MX_FREERTOS_Init()`、`osKernelStart()`。`osKernelStart()` 不返回。

`Os_Init()` 先空等 5 s，每秒喂一次看门狗，再做下面几件事，结束前再喂一次。GPIO 初始化阶段 PB8、PB9 是低电平。打开两只 MOS 的语句已注释，上电后保持关闭，直到状态机离开待机。

1. 校准 ADC1。
2. 调用 `LTC6804_initialize()`：片选拉低 1 ms 唤醒芯片，空等 10 ms，再写入配置。第 0 字节 `0xFC` 打开 REFON，ADCOPT 保持 0。
3. `USART1_Init()` 的调用已注释。USART1 由 Modbus 线程在调度器起来之后打开接收。
4. 调用 `Store_Init()`。返回 0 时把最后一页里的 `soc` 写入 `SOC`，把 `total_voltage` 写入总电压，不写 `InitialSOC`。返回 -1 时这两个量保持 0。

## 调度

运行中的调度见 `docs/RTOS.md`。FreeRTOS 占用 SysTick，`HAL_GetTick()` 在 TIM4。优先级从高到低是电流、控制、电压、数据处理，报告和 Modbus 同为最低。

| 线程 | 周期 | 当前内容 |
| --- | --- | --- |
| 电流 `"current"` | 1 ms | 采一个点。墙钟满 100 ms 就平均、入队、清空窗口 |
| 控制 `"ctrl"` | 无 | 先处理命令，再处理一帧保护结果。走状态机，改 MOS |
| 电压 `"voltage"` | 100 ms | 发 ADCV，等 4 ms，分四组读回，合成一帧 |
| 数据处理 `"data"` | 无 | 等电压帧，取最新电流，做 SOC 和保护 |
| 报告 `"report"` | 1 s | 温度、LED，条件满足才喂狗 |
| Modbus `"mb"` | 1 ms 轮询 | RTU 从机。`0x03` 读测量，`0x06` 把命令送进控制线程 |

旧的协作式槽位调度记在 `docs/时间片调度.md`，程序里已经没有 `Os_Period()` 和 `Os_Task()`。

`SetModelInput()`、`SetModelOutput()` 是空函数。`os.h` 声明了 `ShowInformation()`，工程内没有定义，也没有调用。

## 电流采样

电流在 `sample.c` 里分两步做。电流线程每 1 ms 先拿 SPI 锁再拿 ADC 锁。发 ADCV 前把入窗时刻写成当前节拍加 100 ms，四组读完、放开最后一把锁前改成加 20 ms。这段时间不调用 `Current_SamplePush()`，空等的 4 ms 也在其中。其余节拍读取 PB1（ADC1_IN9），原始码写入长度 100 的窗口。墙钟满 100 ms 时调用 `Current_CalcFromAverage()`。这一窗原始码直接求平均，再换成 0.1 mV 并换算 `Current`，然后清空窗口并入队。平均按 100 ms 墙钟，不按凑满 100 点。

- 12 位、右对齐、软件触发，采样时间 239.5 个 ADC 周期。
- 0.1 mV：`avg_x10 = (raw_sum × 3300 × 10 + 分母 / 2) / (count × 4096)`。分母是本窗点数乘 4096，`3300 × 10` 是一个原始码对应的 0.1 mV。缓冲是 `uint16_t` 原始码，`Current` 是 `int16_t`。
- 偏差是 `delta_x10 = 1361 × 10 - avg_x10`。绝对值不超过 5（±0.5 mV）为 0。超出后乘 `50 / 10`，1 mV 仍是 50。高于零点为负，低于零点为正。超出 `int16_t` 时停在 ±32767。
- 数据处理线程在估算之后写 `OC_FLAG = (Current >= 2000) || (Current <= -2000)`。2000 对应偏置以外 40 mV。两个方向都比较，不看当前状态，没有连续次数。这一拍的结果送到控制线程后，`CriticalFault` 带上这个标志，充电或放电会进入故障并关掉两只 MOS。电流回到门槛内的下一帧把 `OC_FLAG` 写成 0。
- ADC 失败返回 `0xFFFF` 时不入窗。
- 缓冲未满时，平均已经采到的点数。满 100 个后，新点覆盖最旧的点。每 100 ms 平均后窗口清空，下一窗只含新点。

`× 50` 是代码里的比例系数。Modbus 读到的是最近一次 100 ms 算出的 `Current`，高于零点为负。电流采样持有 SPI 锁，读寄存器期间这一毫秒会等到传输结束再采，不会在时钟翻转时读 ADC。窗口点数仍可能少于 100。

## 温度采样

温度在 `sample.c` 的 `Temp_SamplePush()` 里采样。报告线程每 1 s 先拿 SPI 锁再拿 ADC 锁，调用它，再翻转 LED。1 s 一次，采完立刻换算，没有环形缓冲，也没有平均。通道在运行时切换，CubeMX 初始化只配置了通道 9。

按分压关系，10 kΩ 为上拉，NTC 在下方对地：

```
Rt = 10000 × Vadc / (3.3 - Vadc)
T(°C) = 1 / (1/298.15 + ln(Rt/10000) / 3950) - 273.15
```

即 25 °C 时 10 kΩ、B = 3950 的 NTC。结果加 0.5 后截成 `uint8_t`。能通过判断的原始码是 1～4095，对应大约 -90 °C～528 °C。`uint8_t` 放不下 0 °C 以下，高于 255 °C 只留低 8 位。温度不在 Modbus 寄存器里。

ADC 失败、分压为 0 V 或 3.3 V 时直接返回，不改 `temp`，避免 `3.3 - adc` 变成 0。上电后还没有成功采样时，`temp` 为 0。

## 通信

USART1 是 Modbus RTU 从机，115200 8N1，从机地址 1。`mb` 线程在调度器起来之后 `eMBInit()`、`eMBEnable()`，然后每 1 ms 调用 `eMBPoll()`。帧格式和移植层见 `docs/modbus.md`。

功能码 `0x03` 从地址 0 读 5 个保持寄存器：总电压（mV）、电流（`int16_t` 位型）、SOC（0.01%）、充电 MOS、放电 MOS。MOS 读 PB8、PB9，高电平为 1。功能码 `0x06` 只写地址 5：0、1、2、3 分别变成控制线程里的 `S`、`C`、`D`、`Clear`。`usart1.c` 的行解析和五行发送还在，`USART1_Init()` 和 `USART1_SendTxStr()` 的调用已注释。

### 状态机与 MOS

生成代码在 `state_machine_ert_rtw/state_machine.c`。控制线程收到一帧保护结果后，把 `CriticalFault` 写成这一帧的过压、欠压、过流，调用一次 `state_machine_step()`，再调用 `JudgeBMSState()`。命令先改 `StateRequest` 再走状态机；落到待机且请求已经是充电或放电时，同一次处理里再走一步，然后才改 MOS。

| `BMS_State` | MOS |
| --- | --- |
| `BMS_Standby`（0） | 充电、放电都关 |
| `BMS_Driving`（2） | 充电关，放电开 |
| `BMS_Charging`（1） | 放电关，充电开 |
| `BMS_Fault`（3） | 充电、放电都关 |

每次结果处理执行 `CriticalFault = OV_FLAG || UV_FLAG || OC_FLAG`，再调用一次 `state_machine_step()`。`OC_FLAG` 由数据处理线程按平均电流写成 0 或 1。待机时，`StateRequest` 为 `Charging` 优先进入充电，其次才看 `CriticalFault`，最后才是放电请求。已经在充电或放电时，故障优先于请求，直接进入故障；请求变化则先回到待机。同一次 `step()` 不会再从待机跳到另一个运行状态。命令路径在落到待机且请求是充电或放电时会再走一步，所以一条充电或放电命令不用等下一帧电压。故障里忽略 `StateRequest`，只有 `CriticalFault` 变 0 才回到待机。电流回到 ±2000 以内后，下一帧把 `OC_FLAG` 写成 0，再下一帧结果才离开故障。控制线程里的被动均衡调用目前两处都注释，见 `docs/被动均衡.md`。

### 读数从哪来

报告线程每 1 s 采温度、翻转 LED，不再调用 `USART1_SendTxStr()`。测量值由功能码 `0x03` 读出。SOC 仍按万分比存放，寄存器里就是这个整数。电流寄存器是 `Current` 的位型。Store 的三处成功提示已注释，不再占用 USART1。

## 单体电压

电压线程每 100 ms 在 SPI 锁里调用 `LTC6804_adcv()`，然后放开锁，`osDelay(4)`。本线程的 `cell_codes[12]` 保存 12 节原始码，上电为 0。

1. ADCV 命令高字节 `0x03`、低字节 `0x60`，PEC 由 `pec15_calc()` 现算。片选拉低只包住这 4 个字节。通道位 CH 是 `000`，12 节一起转换。模式位 MD 是 `10`，即 7 kHz。放电允许位 DCP 是 0，转换期间暂停放电。
2. 电压线程用 `osDelay(4)` 等转换结束。初始化已把 REFON 打开，每次转换不再等待基准上电。7 kHz 全节转换大约 2.3 ms，4 ms 门槛盖住这次转换。等待期间不持有 SPI 锁。发 ADCV 前入窗时刻已经写成当前节拍加 100 ms，所以这 4 ms 不入电流窗口。
3. 时间到了之后，四组各拿一次 SPI 锁，调用 `LTC6804_rdcv_group()`。命令分别是 `0x0004`、`0x0006`、`0x0008`、`0x000A`。每组时钟出 8 字节：6 字节电压加 2 字节 PEC。
4. PEC 通过后，按低字节在前解析 3 节，写入这一组的 3 个原始码。1 LSB = 100 µV。PEC 失败则这一组保持旧值，并在 `pec_mask` 里记下这一组。
5. 毫伏是原始码除以 10。12 节相加得到 `uint16_t` 总电压。整帧放进深度为 1 的电压队列。数据处理线程取出后写入 `cell_voltage[]` 和 `total_voltage`，再调用 `SOC_Estimator()` 和 `protect_step()`。状态机在控制线程。Modbus 这一步不读单体电压。下标 0 是第 1 节。ADCV 每 100 ms 一次，读数大约在发命令 4 ms 之后更新。`pec_mask` 目前没有被读取。

## SOC

`Get_SOC_From_OCV()` 按单体毫伏做整数线性插值，返回万分比。电压大于等于 4200 mV 返回 10000，小于等于 3100 mV 返回 500。4200、4150、4100 mV 对应 10000、9500、9000。4050 mV 是 8800，之后到 3500 mV 每 50 mV 降 100，3500 mV 是 7700。3450 mV 对应 4000。3400、3300、3200、3100 mV 对应 3000、2000、1000、500。

平均单体电压是 `(total_voltage + 4) / 9`。实际接了 9 节。未接的第 6、11、12 节为 0 时，12 路之和除以 9 就是这 9 节的平均。未接通道如果读到非 0，仍会加进 `total_voltage`。

`SOC_Estimator()` 在总电压换成毫伏之后调用。`total_voltage == 0` 时直接返回。`InitialSOC != 0` 时调用 `Ah_Integrator_Estimator_step()`。这一拍的 `SOC` 大于等于 8000 或小于等于 3000，并且和查表值相差超过 1000 时，把 `SOC` 和 `InitialSOC` 改成查表值，再调用 `Ah_Integrator_Estimator_initialize()` 把积分量写成 0。

`InitialSOC` 为 0 时不积分。查表值和当前 `SOC` 相差超过 1000 就把 `SOC` 改成查表值，再把 `InitialSOC` 写成这个 `SOC`，并清掉积分量。相差不超过 1000 时保留当前 `SOC`，只把它写入 `InitialSOC`。Flash 里的 `soc` 因此可以成为积分起点。当前 `SOC` 仍是 0 时，`InitialSOC` 也仍是 0。查表结果小于等于 1000，也就是平均单体电压不高于 3200 mV，跨不过这个门槛，`SOC` 停在 0，积分不会开始。

数据处理线程用本拍单体电压覆盖总电压，所以上面的查表用的是本拍平均，不是 Flash 里保存的旧总电压。控制线程收到 `S` 后先走完状态机，再把已经发布的 `SOC` 和 `total_voltage` 写入最后一页。

积分模型版本 1.49。它读 `Current` 和 `InitialSOC`，两边都按万分比衔接。额定容量 `Q_rated = 1200`，库伦效率 `eta_coulomb = 0.99`，类型是 `real32_T`。积分每次加上 `0.99 × Current × 0.1`，正电流和负电流都乘这个系数。电压大约每 100 ms 读一次，和这个 0.1 s 步长一致。结果是 `(积分量 / (3600 × Q_rated) + 9.99998301e-5 × InitialSOC) × 10000`，再收成 `uint16_T` 的 `SOC`。`InitialSOC` 为 7800、积分量仍为 0 时，结果仍是 7800。两端改写或第一次写入 `InitialSOC` 时都会把积分量清 0，下一拍从新的 `InitialSOC` 重新累加。

## 过充与过放

手写的 `Judge_CHG_DSG()` 和 `Get_Cell_Voltage_Max_Min()` 已整段注释，留在 `switch.c`。正在使用的开关函数也在这个文件里：单独打开或关闭充电、放电，以及两只一起关。标志改由 `protect_ert_rtw/protect.c`（模型 1.38）在数据处理线程里计算。它比较的是本拍毫伏。`OC_FLAG` 不由 `protect_step()` 计算。控制线程把 `CriticalFault` 写成这一帧的过压、欠压、过流，再调用 `state_machine_step()`。`JudgeBMSState()` 仍在 `os.c`，按 `BMS_State` 调用 `switch.c` 里的函数。故障时关掉两只 MOS。

取最小之前，等于 0 mV 的节换成 9999 mV，未接的三节因此不拉低最小。最大仍用原始毫伏，0 mV 也不会抬高最大。状态只有正常、过压、欠压三种，不能同时置两个标志。第一次 `protect_step()` 只进入正常并把两个标志清 0，不看电压。之后：

| 当前状态 | 条件 | 结果 |
| --- | --- | --- |
| 正常 | 最小节 `< 2800` mV | 欠压，`UV_FLAG = 1` |
| 正常 | 否则最大节 `> 4200` mV | 过压，`OV_FLAG = 1` |
| 过压 | 最大节 `< 4100` mV | 回到正常，两个标志清 0 |
| 欠压 | 最小节 `> 3100` mV | 回到正常，两个标志清 0 |

未接三节保持 0 mV 时，不会再把欠压锁住。等于 0 mV 的已接节同样被换成 9999 mV，不参与欠压。非 0 的读数，包括未接通道上的噪声和约 6553 mV 的 `0xFFFF`，仍参与最大，也会参与最小。`Temp_up_flag` 已定义。`OC_FLAG` 由 100 ms 平均电流写成 0 或 1，不在 `protect_step()` 里。单次采样返回 -1 的判断仍注释着。

SPI 仍是模式 3、软件片选 PA4、SCK 约 281.25 kbit/s，接的是芯片的 SPI 口。`LTC6804_initialize()` 上电时把片选拉低 1 ms 做一次唤醒，空等 10 ms，再调用 `LTC6804_wrcfg()` 写入 `0xFC`。

看门狗超时大约 2 s，超时后整片进入睡眠。100 ms 就会发一次 ADCV，大约 4 ms 后再读寄存器，间隔小于 2 s，芯片不会在两次采样之间睡下去，所以每次测量前不必再唤醒。大约 5.5 ms 的那个时间是 isoSPI 口自己的空闲超时，不是这颗芯片接 SPI 时的睡眠看门狗。

## 运行关系

```
电流线程 1 ms
    └── 避开 SPI 后采一个点。满 100 ms 平均、入队、清空窗口

电压线程 100 ms
    └── 发 ADCV，放开锁等 4 ms，四组各读一次，合成一帧

数据处理线程
    └── 等电压帧，取最新电流，SOC_Estimator()，写 OC_FLAG，protect_step()，发布快照

控制线程
    ├── 命令：S / C / D 写 StateRequest，Clear 只擦页。S 在状态机之后保存
    └── 结果：写 CriticalFault，走一次状态机，按 BMS_State 重写两只 MOS

报告线程 1 s
    ├── 避开 SPI 后采温度，翻转 LED
    └── 三条存活标志都在且栈余量够，才喂狗

Modbus 线程
    └── 每 1 ms 轮询。0x03 读寄存器，0x06 把 S / C / D / Clear 放进命令队列
```

## 当前没有完成的部分

- 某一组 PEC 失败时，该组保持旧码，其余组仍更新。`pec_mask` 记了失败的组，数据处理线程不读它。该组若还从未通过，已接节保持 0 mV，保护里会被换成 9999 mV，不会触发欠压。原始码 `0xFFFF` 会换成约 6553 mV，计入总电压，并因为大于 4200 mV 进入过压。
- `InitialSOC` 为 0 且当前 `SOC` 为 0 时，平均单体电压不高于 3200 mV 不会开始积分。两端校准用的是当前端电压，30% 以下大约 100 mV 就会改写 `SOC` 并清掉积分量。收到 `S` 时写入的是数据处理线程已经发布的那一拍。程序区长度是 `0xFC00`，最后一页留给 Store。
- `SetModelInput()`、`SetModelOutput()` 为空，`ShowInformation()` 没有实现。`RECEICE_DATA_DEAL()` 和 `OnUartLine()` 不在接收路径上。
- 电流高于偏置为负，低于偏置为正。超出 `int16_t` 时停在 ±32767。待机时充电请求优先于 `CriticalFault`，过流标志为 1 仍会进入充电。均衡写配置的两处调用仍注释，硬件没有做均衡。
- 等于 0 mV 的节只在取最小时换成 9999 mV。未接通道若读到非 0，仍会参加过压和欠压。已接节若一直是 0 mV，也不会进入欠压。第一次 `protect_step()` 不看电压，门槛从下一次读取才生效。电流消息里的 `count` 没有被读取，积分步长仍按 0.1 s。
