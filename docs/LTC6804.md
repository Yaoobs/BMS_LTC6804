# LTC6804

单体电压由一颗 LTC6804 测量，MCU 用 SPI1 直接连接，不是 isoSPI。驱动在 `Core/PeripheralSrc/LTC6804.c`。何时发命令、何时读回在电压线程，步骤见 `docs/RTOS.md`。电压线程发 ADCV 后放开 SPI 锁，等 4 ms，再分四组调用 `LTC6804_rdcv_group()`。

## 现状

### 连接

| 项 | 内容 |
| --- | --- |
| 片选 | PA4，软件控制，空闲为高 |
| SPI | PA5 / PA6 / PA7，模式 3（CPOL=1，CPHA=1） |
| 时钟 | 72 MHz / 256 ≈ 281.25 kbit/s |
| 片数 | 测量路径按 1 颗、12 节来写 |
| 原始码 | `cell_codes[12]`，下标 0 是第 1 节 |

片选只包住这一次命令或这一次读回。读的时候 MOSI 送 `0x00`，芯片在读寄存器时不使用 SDI。

### 上电

`Os_Init()` 调用 `LTC6804_initialize()`：片选拉低 1 ms（`wakeup_idle()`），空等 10 ms，再调用 `LTC6804_wrcfg()` 写一次配置。第 0 字节是 `0xFC`：GPIO1～GPIO5 保持 1，REFON 打开，ADCOPT 为 0，因此后面的 ADCV 仍是 7 kHz。其余 5 字节为 0，不开启均衡。读配置没有调用。

芯片内部看门狗大约 2 s 没有有效通信就会睡眠。现在每 100 ms 发一次 ADCV，间隔小于 2 s，运行中不会在两次测量之间睡下去，所以每次测量前不再唤醒。大约 5.5 ms 的那个时间是 isoSPI 口自己的空闲超时，这套接线用不到。

### 命令和 PEC

命令是 2 字节加 2 字节 PEC15。`pec15_calc()` 初值 16，结果再乘 2，和手册的 PEC15 一致。发出去的 PEC 每次现算。

ADCV 现在的两个命令字节是 `0x03`、`0x60`：

| 位 | 值 | 含义 |
| --- | --- | --- |
| MD | `10` | 7 kHz 模式 |
| DCP | `0` | 转换期间不开启均衡 |
| CH | `000` | 12 节一起转换 |

读寄存器按组进行，每组 3 节，命令如下。每组时钟出 8 字节：6 字节电压加 2 字节 PEC。

| 组 | 命令 | 写入 `cell_codes` |
| --- | --- | --- |
| RDCVA | `0x0004` | `[0]`～`[2]` |
| RDCVB | `0x0006` | `[3]`～`[5]` |
| RDCVC | `0x0008` | `[6]`～`[8]` |
| RDCVD | `0x000A` | `[9]`～`[11]` |

电压字节是低字节在前。1 LSB = 100 µV。PEC 与收到的两字节一致才写入这 3 节；不一致则这 3 节保持上一次的码，函数返回 -1。四组都读完后，只要有一组失败，`LTC6804_rdcv()` 的返回值就是 -1。

### 一次测量

电压线程每 100 ms 在 SPI 锁里调用 `LTC6804_adcv()`，然后放开锁，`osDelay(4)`。本线程的 `cell_codes[12]` 上电为 0。

REFON 已经在初始化时打开。7 kHz、12 节一起转换大约 2.3 ms。等待 4 ms 盖住这次转换。等待期间不持有 SPI 锁，电流线程可以采样。

四组各拿一次锁，调用 `LTC6804_rdcv_group()`。一组大约 0.3 ms。`HAL_SPI_Transmit()` 和 `HAL_SPI_TransmitReceive()` 的超时是 2 ms。PEC 失败的那一组保持旧码，并记进 `pec_mask`。`LTC6804_rdcv()` 仍一次读完四组，电压线程不调用它。

毫伏是原始码除以 10，12 节相加得到总电压，整帧入队。数据处理线程写入 `cell_voltage[]` 和 `total_voltage`，再 `SOC_Estimator()`、`protect_step()`。控制线程写 `CriticalFault` 并走状态机。不足 1 mV 的部分被丢掉。Modbus 这一步不读单体电压。`pec_mask` 目前没有被读取。

原始码 `0xFFFF` 若 PEC 通过，会写成约 6553 mV。芯片用这个码表示尚未得到有效转换。

### 配置寄存器

`LTC6804_wrcfg()` 只服务 1 颗芯片。命令是 `0x0001`，PEC 写死为 `0x3D6E`，后面跟 6 字节配置和这 6 字节的 PEC，一共 12 字节。它自己不再拉低片选唤醒，调用前要保证芯片是醒的。初始化在 `wakeup_idle()` 之后写一次，DCC 和 DCTO 为 0。`send_balance_commend()` 和 `exit_balance_commend()` 已写好，控制线程里的调用保持注释，运行中不会再写配置。字节含义见 `docs/被动均衡.md`。

`LTC6804_rdcfg()` 读命令 `0x0002`，PEC 为 `0x2B0A`，把 8 字节交给调用方。PEC 失败返回 -1，缓冲区里仍是刚读到的字节。当前没有调用。

PEC 表 `crc15Table[256]` 放在 `LTC6804.c` 里。

## 优化项

1. **四组寄存器已经拆开读。** 电压线程等 4 ms 后每次只读一组，读完再合成一帧。一组大约 0.3 ms。电流采样持有同一把 SPI 锁，传输期间等到结束再采，不再靠 1 ms 标志补采。

2. **使用 `LTC6804_rdcv()` 的返回值，并识别 `0xFFFF`。** 现在 PEC 失败只留下旧码，调用方看不出来。`0xFFFF` 通过 PEC 后会变成约 6553 mV，总电压和 SOC 会把这个数加进去。失败的组和 `0xFFFF` 不要换算成毫伏。读早于大约 2.3 ms 时就会碰到这个码。

3. **检查 SPI 是否真正完成。** 超时或错误时，读缓冲里的字节不一定是芯片送出的。这种组不要拿去比 PEC，更不要写入 `cell_codes[]`。

4. **测量路径不要调用 `wakeup_idle()`。** 它里面是 `HAL_Delay(1)`。初始化时调用一次可以接受。运行中的 100 ms ADCV 已经短于 2 s 看门狗，不需要为 isoSPI 空闲超时做唤醒。写配置之前的那一次唤醒留在 `LTC6804_initialize()` 里。电压线程没有调用它。
