# LTC6804

单体电压由一颗 LTC6804 测量，MCU 用 SPI1 直接连接，不是 isoSPI。驱动在 `Core/PeripheralSrc/LTC6804.c`，何时发命令、何时读回在 `os.c`。

## 现状

### 连接

| 项 | 内容 |
| --- | --- |
| 片选 | PA4，软件控制，空闲为高 |
| SPI | PA5 / PA6 / PA7，模式 3（CPOL=1，CPHA=1） |
| 时钟 | 72 MHz / 256 ≈ 281.25 kbit/s |
| 片数 | 测量路径按 1 颗、12 节来写 |
| 原始码 | `cell_codes[12]`，下标 0 是第 1 节 |

片选只包住这一次命令或这一次读回。读的时候 MOSI 送 `0x00`，芯片在读寄存器时不使用 SDI。

### 上电

`Os_Init()` 调用 `LTC6804_initialize()`：片选拉低 1 ms（`wakeup_idle()`），空等 10 ms，再调用 `LTC6804_wrcfg()` 写一次配置。第 0 字节是 `0xFC`：GPIO1～GPIO5 保持 1，REFON 打开，ADCOPT 为 0，因此后面的 ADCV 仍是 7 kHz。其余 5 字节为 0，不开启均衡。读配置没有调用。

芯片内部看门狗大约 2 s 没有有效通信就会睡眠。现在每 100 ms 发一次 ADCV，间隔小于 2 s，运行中不会在两次测量之间睡下去，所以每次测量前不再唤醒。大约 5.5 ms 的那个时间是 isoSPI 口自己的空闲超时，这套接线用不到。

### 命令和 PEC

命令是 2 字节加 2 字节 PEC15。`pec15_calc()` 初值 16，结果再乘 2，和手册的 PEC15 一致。发出去的 PEC 每次现算。

ADCV 现在的两个命令字节是 `0x03`、`0x60`：

| 位 | 值 | 含义 |
| --- | --- | --- |
| MD | `10` | 7 kHz 模式 |
| DCP | `0` | 转换期间不开启均衡 |
| CH | `000` | 12 节一起转换 |

读寄存器按组进行，每组 3 节，命令如下。每组时钟出 8 字节：6 字节电压加 2 字节 PEC。

| 组 | 命令 | 写入 `cell_codes` |
| --- | --- | --- |
| RDCVA | `0x0004` | `[0]`～`[2]` |
| RDCVB | `0x0006` | `[3]`～`[5]` |
| RDCVC | `0x0008` | `[6]`～`[8]` |
| RDCVD | `0x000A` | `[9]`～`[11]` |

电压字节是低字节在前。1 LSB = 100 µV。PEC 与收到的两字节一致才写入这 3 节；不一致则这 3 节保持上一次的码，函数返回 -1。四组都读完后，只要有一组失败，`LTC6804_rdcv()` 的返回值就是 -1。

### 一次测量

`Task_100ms()` 在电流平均之后调用 `LTC6804_adcv()`，然后记下 `HAL_GetTick()`，把 `adcv_wait` 置 1。

`Os_Task()` 在各周期任务之前调用 `Voltage_Poll()`。差值还不到 4 ms 就直接返回。到了 4 ms，把 `adcv_wait` 清 0，再一次调用 `LTC6804_rdcv(cell_codes)`。同一次循环里若 100 ms 任务也到期，会先读走上一次的结果，再发下一次 ADCV。

REFON 已经在初始化时打开，每次 ADCV 不再包含基准上电。7 kHz、12 节一起转换大约 2.3 ms。`HAL_GetTick()` 是 1 ms 一步，比较值是 4：读的时刻至少过了大约 3 ms。写成 3 时，真实时间可能刚过 2 ms 就去读，短于 2.3 ms。等待期间主循环继续转。

四组 SPI 加在一起大约 1.4 ms。`HAL_SPI_Transmit()` 和 `HAL_SPI_TransmitReceive()` 的超时是 2 ms，单次事务短于这个超时。返回值没有检查。`LTC6804_rdcv()` 的返回值也没有检查。

读完寄存器后，`Voltage_Poll()` 先调用 `Get_TotalVoltage()`，把每节 `cell_codes[i] / 10` 截成毫伏再累加，再调用 `SOC_Estimator()`，然后调用 `protect_step()`。接着把 `CriticalFault` 写成过压、欠压、过流三个标志的或，走一次状态机并改 MOS。被动均衡的写配置目前整段注释，见 `docs/被动均衡.md`。不足 1 mV 的部分被丢掉。文本上报不带单体电压。解析函数注释里的 `Get_Cell_Voltage()` 工程里没有这个函数。

原始码 `0xFFFF` 若 PEC 通过，会写成约 6553 mV。芯片用这个码表示尚未得到有效转换。

### 配置寄存器

`LTC6804_wrcfg()` 只服务 1 颗芯片。命令是 `0x0001`，PEC 写死为 `0x3D6E`，后面跟 6 字节配置和这 6 字节的 PEC，一共 12 字节。它自己不再拉低片选唤醒，调用前要保证芯片是醒的。初始化在 `wakeup_idle()` 之后写一次，DCC 和 DCTO 为 0。`send_balance_commend()` 和 `exit_balance_commend()` 已写好，`Voltage_Poll()` 里的调用目前整段注释，运行中不会再写配置。字节含义见 `docs/被动均衡.md`。

`LTC6804_rdcfg()` 读命令 `0x0002`，PEC 为 `0x2B0A`，把 8 字节交给调用方。PEC 失败返回 -1，缓冲区里仍是刚读到的字节。当前没有调用。

PEC 表 `crc15Table[256]` 放在 `LTC6804.c` 里。

## 优化项

1. **四组寄存器拆开读。** 一次读完大约 1.4 ms，长于 1 ms 电流周期，而且读发生在电流采样之前。1 ms 标志只有一位，读的过程里再来一次节拍会和原有的标志合成一次，每 100 ms 少一个电流点。一组大约 0.3 ms。时间到了之后每次主循环只读一组，四组都读完再把 `adcv_wait` 清 0。调度上的影响写在 `docs/时间片调度.md`。

2. **使用 `LTC6804_rdcv()` 的返回值，并识别 `0xFFFF`。** 现在 PEC 失败只留下旧码，调用方看不出来。`0xFFFF` 通过 PEC 后会变成约 6553 mV，总电压和 SOC 会把这个数加进去。失败的组和 `0xFFFF` 不要换算成毫伏。读早于大约 2.3 ms 时就会碰到这个码。

3. **检查 SPI 是否真正完成。** 超时或错误时，读缓冲里的字节不一定是芯片送出的。这种组不要拿去比 PEC，更不要写入 `cell_codes[]`。

4. **测量路径不要调用 `wakeup_idle()`。** 它里面是 `HAL_Delay(1)`。初始化时调用一次可以接受。若放进 100 ms 任务或 `Voltage_Poll()`，主循环又会被空等占住。运行中的 100 ms ADCV 已经短于 2 s 看门狗，不需要为 isoSPI 空闲超时做唤醒。写配置之前的那一次唤醒留在 `LTC6804_initialize()` 里。
