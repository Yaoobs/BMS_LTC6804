# 电流与温度采集

电流和温度共用 ADC1。`adc.c` 负责启动一次转换并读出原始码，`sample.c` 负责换成物理量。电流在这里做滑动平均，温度不做平均。触发点在 `os.c`：1 ms 采电流，100 ms 算电流；1 s 采一次温度并立刻换算。

## 现状

### ADC1 怎么配

| 项 | 内容 |
| --- | --- |
| 电流 | PB1，ADC1_IN9 |
| 温度 | PA0，ADC1_IN0，NTC |
| 时钟 | PCLK2 / 6 = 12 MHz |
| 分辨率 | 12 位，右对齐，单次转换 |
| 扫描 / 连续 | 都关闭，规则组只有 1 个通道 |
| 触发 | 软件触发 |
| 采样时间 | 239.5 个 ADC 周期 |
| 一次转换 | 239.5 + 12.5 = 252 个周期，约 21 µs |
| 中断 / DMA | 没有打开。工程里没有 ADC 中断，也没有 `MX_DMA_Init()` |
| 定时器 | `HAL_TIM` 未启用，没有定时器触发 ADC |

`MX_ADC1_Init()` 只把规则组配成通道 9。通道 0 在每次读温度时由 `Get_Adc1Value()` 再写进去。`Os_Init()` 里调用一次 `HAL_ADCEx_Calibration_Start()`，之后不再校准。

### 读一次的过程

`Get_Adc1Channe9Value()` 和 `Get_Adc1Channe0Value()` 都进 `Get_Adc1Value()`：

1. `HAL_ADC_ConfigChannel()` 把规则组改成这次要的通道，采样时间仍是 239.5 周期。
2. `HAL_ADC_Start()` 软件启动。
3. `HAL_ADC_PollForConversion()` 空等转换结束，超时 10 ms。
4. 成功则返回 0～4095。启动或等待失败返回 `0xFFFF`。电流和温度都拿这个值判断，失败样本不参与换算。

轮询期间主循环停在这次调用里。一次大约 21 µs，相对 1 ms 周期可以忽略。真正会拖住主循环的是 `Voltage_Poll()` 一次读完四组电压寄存器，大约 1.4 ms。1 s 上报已经改成中断发送，不再占着主循环，见 `docs/时间片调度.md`。

两路不能同时转换。ADC1 只有一个规则组，电流和温度靠每次改通道轮流使用。

### 电流

`Task_1ms()` 调用 `Current_SamplePush()`：

- 原始码换成毫伏：`(int)(3.3 * Adc_value / 4096 * 1000)`，1 LSB 约 0.81 mV。除数是 4096。
- 失败码不入队。窗口里的个数会少一个，100 ms 仍用现有个数平均。
- 毫伏写入长度 100 的环形缓冲。满了以后新值覆盖最旧的值。100 个点 × 1 ms 等于 100 ms。

`Task_100ms()` 发 ADCV 之前调用 `Current_CalcFromAverage()`：

- 对缓冲里已有的毫伏求和，四舍五入：`(sum + count / 2) / count`。`sum` 是 `uint32_t`。
- 偏置 `CURRENT_ADC_BASE_MV = 1368`。平均毫伏大于 1370 时，`Current = -(adc - 1368) * 50`；小于 1366 时，`Current = (1368 - adc) * 50`；1366～1370 为 0。`Current` 是 `int16_t`，高于偏置为负，低于偏置为正。
- 单次毫伏差大于 40 mV 就返回 -1 的判断已注释，现在每笔有效采样都入队。ADC 失败返回 -2，不入队。

1 ms 任务排在 100 ms 任务前面。同一次 `Os_Task()` 里若两个标志都置位，先入队再平均，这次新采样会进入当次平均。

采样只发生在 `Task_1ms()` 真的跑到的时候。`Voltage_Poll()` 一次读四组大约 1.4 ms，1 ms 标志只能记住一次，每 100 ms 会少一次电流入队。ADC 在 SPI 读取期间是空闲的，不会自己补采。

### 温度

`Task_1000ms()` 先翻转 LED，再调用 `Temp_SamplePush()`，采一次 PA0，马上换成温度，没有缓冲，也没有平均。函数名仍带 Push，里面已经不再入队。

- 原始码换成分压：`(float)(3.3 * Adc_value / 4096)`，单位伏特。
- 上拉 10 kΩ 到 3.3 V，NTC 到地。`Rt = 10000 * V / (3.3 - V)`。
- R25 = 10 kΩ，B = 3950。`temp` 现为 `uint8_t`。原始码 1～4095 对应大约 -90 °C～528 °C。0 °C 以下和高于 255 °C 都会被这个类型截断。
- ADC 失败、分压小于等于 0 或大于等于 3.3 时直接返回，`temp` 保持上一次的值。上电后还没有成功采样时，`temp` 为 0。
- 1 s 文本不上报温度。`temp` 仍保留，未调用的 `USART1_SendTxData()` 会把它放进 50 字节帧的第 38 字节。

温度采样在 1 s 任务里，大约 21 µs，再加一次 `logf()`。电压读取已经不在这条任务里空等。

## 优化项

一次轮询大约 21 µs，短于 1 ms。把 `HAL_ADC_PollForConversion()` 换成转换完成中断，只能省掉这 21 µs 的空等。启动仍然写在 1 ms 任务里。主循环被 1.4 ms 的电压读取挡住时，下一次电流转换不会开始，这一拍采样会丢。

电流改成定时器触发、DMA 搬运，主循环里不再为这一路做 1 ms 轮询。平均、40 mV 偏离和死区留在 100 ms 任务。温度仍是 1 s 轮询一次，不进 DMA，也不做平均。

### 1. 定时器触发规则组 + DMA

F103 的 ADC DMA 只服务于规则组，请求在规则转换结束时发出，数据来自 `DR`。注入组的 `JDR` 不能走 DMA。所以 IN9 要放在规则组，不能沿用注入组加 JEOC 中断的接法。温度改挂注入组，触发方式仍是 1 s 任务里软件启动并轮询，节拍不变。

- TIM3 仍是 1 ms。APB1 为 36 MHz，定时器时钟 72 MHz，预分频 71、自动重装 999。规则组的外部触发是 TIM3 的 TRGO，不是通道 4。主模式选更新事件 `TIM_TRGO_UPDATE`。
- 规则组只排 IN9，扫描和连续都关闭。`HAL_ADC_Start_DMA()` 在外部触发已经选好时，只置 `EXTTRIG`，不会立刻软件启动。每次 TRGO 转换完，DMA1 通道 1 从 `DR` 搬一个 16 位原始码。该通道目前空闲。
- 缓冲用循环模式，长度 100，和现在的平均窗口一样。`Task_1ms()` 不再读电流。`Task_100ms()` 按 DMA 的 `CNDTR` 避开正在写的那一格，把其余点换成毫伏。与 1368 mV 相差大于 40 mV 的点不参与平均，并关掉两只 MOS。死区和 `× 50` 仍只用通过的点。高于偏置仍为负，低于偏置仍为正。
- 关断因此从每 1 ms 判断变成在 100 ms 任务里判断，最多晚大约 100 ms，再加主循环当时正在做的 SPI 读取。`HAL_ADC_Start_DMA()` 会打开 DMA 半传输和传输完成中断，缓冲长度为 100 时大约每 50 ms、100 ms 进一次中断，不是每 1 ms。回调可以空着。若连这次也不要，用 `HAL_DMA_Start()` 启动通道，不要用 `HAL_DMA_Start_IT()`。
- 注入组只排 IN0，采样时间 239.5 周期，不要打开 `JAUTO`，否则每次电流转换都会连带采温度。1 s 任务调用注入组软件启动，轮询 JEOC，读 `JDR1`。不要再 `HAL_ADC_ConfigChannel()`，也不要停 TIM3。
- 两组共用一个转换器。1 s 里那次注入转换如果碰上电流转换，电流转换会在注入结束后重做，DMA 拿到的仍是 IN9。校准完成后再开 TIM3。

这样主循环被 1.4 ms 的电压读取挡住时，电流仍按 1 ms 进缓冲。

两路都放进规则组也可以，但不能只靠一个标志在电流转换期间跳过温度。规则组同时只有一套通道和一种触发。DMA 开着时，`DR` 里每个结果都会进电流缓冲。若在 TIM3 仍触发的情况下把通道改成 IN0，这一拍温度码会被当成电流。它通常离 1368 mV 很远，100 ms 任务会把它判成超过 40 mV，并关掉两只 MOS。

标志要表示的是整段让路，不是单次转换的 21 µs。1 s 任务采温度前关掉 TIM3 的 TRGO 并停掉 DMA，把规则组改成 IN0，软件触发并轮询，读完再改回 IN9，重新打开 DMA 和 TRGO。转换本身大约 21 µs，远短于 1 ms，紧接在一次电流转换结束之后做，通常赶在下一次 TRGO 之前完成，电流可以不丢点。若这次切换跨过了 TIM3 的节拍，丢掉的是这一拍电流，温度仍保持上一次的值。

只在看到“正在转换”时直接返回、不改通道，温度会一直采不到，因为规则组将一直停在 IN9。电流转换并不会自己把这个标志置位；没有 1 ms 中断时，只能由 1 s 任务在动手之前查 ADC 是否忙，并在让路期间自己置位。

### 2. 定时器触发 + 扫描 + DMA

这一档把温度也放进每 1 ms 的扫描，和上面“温度仍 1 s 轮询”不是同一条路径。ADC1 的规则组 DMA 固定走 DMA1 通道 1。

- 打开扫描，规则组两个排名：先 IN9，再 IN0。`NbrOfConversion = 2`。采样时间可以继续用 239.5 周期，两路合计约 42 µs。
- 定时器每 1 ms 触发一次，DMA 循环模式把这一对 16 位结果写入内存。半传输或传输完成时倒换缓冲，任务侧只读已经写完的那一半，避免平均读到写了一半的点。
- 电流仍取最近 100 个点，在 100 ms 任务里平均。这 100 个点由 DMA 在 100 ms 内写满，即使 `Task_1ms()` 没跑到，窗口里也是实采的 100 次。
- 温度现在是 1 s 一次、不做平均。放进这条 1 ms 扫描后，它会跟着每 1 ms 采一次。1 s 任务仍只取最新一个点做 NTC，不必为温度再做滑动平均。
- 缓冲索引若在中断和主循环两边使用，要做成单写单读，或在拷贝这 10 个点时短关中断。

连续转换、不挂定时器时，ADC 会以约 47.6 kSPS 空转。电流和温度都不需要这个速率。若以后要在一次采样里做多次过采样再平均，可以让定时器触发一小段扫描，DMA 收完再停，而不是一直连续转换。

F103C8 有 ADC1 和 ADC2，双 ADC 同步模式可以让两路在同一时刻转换。电流和温度的带宽差很多，没有必要对齐到同一次采样。

### 3. 和调度一起看的顺序

电压等待已经移出主循环。按第 1 节接上 TIM3 和 DMA 之后，读四组寄存器的 1.4 ms 不再漏掉电流采样。温度仍然 1 s 一次。1 s 上报也不再阻塞。

下面几件保持不变：

- 校准仍在启动转换之前做一次。
- 通道序列固定后，不再每次采样都 `HAL_ADC_ConfigChannel()`。
- 死区仍作用在平均毫伏上。逐点做死区会把噪声钳成 0，平均之后死区消失。
- 与 1368 mV 相差大于 40 mV 的点不参与平均。DMA 会把原始码都写进缓冲，筛选放在 100 ms 任务里。DMA 出错时看 overrun，不要把缓冲里的旧值当成新采样。
